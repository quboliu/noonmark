# 烛龙会话交互 R2.2 历史决策记录

> HISTORICAL DECISION RECORD — 本文只保留 R2.2 三个候选模型的比较依据与已确认结论，不再描述当前可运行界面。三个候选均未连接 Provider、SQLite、Keychain 或真实 Todo 写入。

## 要回答的问题

当用户带着一个模糊且较大的任务进入烛龙时，哪种交互模型最能同时表达：

1. grill 式持续澄清；
2. 用户输入怎样改变烛龙的理解与下一步；
3. 可暂停、可介入的委托式规划；
4. 白盒依据、明确边界与不确定性；
5. 一份逐步成形、最终可审查的规划简报。

R2.2 曾把三个结构不同的方案挂在同一任务成形路由中进行比较。比较已于 2026-07-10 完成；候选路由、独立内存状态、prototype switcher 和键盘切换均已退出当前 R3 运行时。下文的 A／B／C 结构只作为当时的设计证据。

## 为什么重新开放方案

上一轮把会话收敛为固定五阶段和单题问题卡，实际运行产物证明这仍是一条预写审批向导：固定“问题 4 / 7”、自然语言输入不进入状态、用户决定不改变后续简报、委托后瞬间出现硬编码 Todo。它没有建立“用户输入 → 烛龙理解变化 → 下一步变化 → 工作产物变化”的可见因果链。

因此，R2.1 的视觉宿主继续有效，关于单一交互结构已经收敛的结论失效。

## 共同产品与视觉契约

- 使用真实 Noonmark Mac 宿主：`240px Sidebar`、页面自己的 `PageHeader`、系统字体、紧凑描边控件与 `#2961C7` accent。
- 主窗口按 `1320 × 820` 设计，并在 `1180 × 760` 验证；窗口、导航、字体、颜色、圆角和边线继续遵守 R2.1 的原生视觉 prompt。
- 会话只有一个主要意图，可以暂停、恢复、追加更正、归档或整体删除；旧内容不得静默改写。
- 代表场景固定为“完整重做烛龙 Agent”，当前真正未决的是第一条可用路径与完成标准。
- 不预告固定题数。状态只描述现实：`等你回答`、`正在整理`、`运行到决策门`、`简报待审`。
- 每次用户动作必须在界面中显示完整相关状态，并明确标出刚改变的字段、运行步骤或下一问题。
- 允许自然语言回答、建议选项、`不知道` 和追加更正；没有回答时不能继续。
- 规划简报必须包含目标、完成标准、硬约束、用户取舍、授权自主事项、烛龙假设、未决问题与数据范围。
- 规划委托和 Todo 写入严格分离。Todo 变更 diff 是后续唯一写入依据，本轮代表场景不执行真实写入。
- 白盒采用三层：动作旁轻提示、当前对象的依据检视、append-only 烛龙事件历史；展示 AI 决策说明，不展示原始 chain-of-thought。
- `#7C5CFF` 只用于烛龙导航图标及淡 active tint；产品主操作继续使用现有蓝色描边／soft fill。
- 当时用于比较的 prototype switcher 从未属于候选产品界面，并已随 R2.2 runtime 一并清理。

## A — 协作会话流（Bounded Dialogue）

### 交互主张

烛龙首先是一场围绕同一任务、会产生正式工作稿的连续协作。它需要保留 grill 的上下文和节奏，但不能成为通用聊天页。

### 像素级结构

- PageHeader 下使用一条 `34px` 会话状态带，显示“等你回答”“简报 v0.4”“本轮不写入 Todo”，不显示固定五阶段。
- 主区 padding `20px 24px 40px`，阅读宽度不超过 `720px`。
- 会话按纵向工作记录排列。每个回合使用 `68px 来源／时间列 + 1fr 内容列`，回合之间为 `1px #E6E6E9` 分隔，不使用头像或聊天气泡。
- 用户原始意图、烛龙复述、已确认决定和当前问题保留在同一滚动上下文；较早回合可以压缩成一行摘要。
- 当前烛龙回合使用 `#FBFBFC` surface；其顶部先说明“我现在这样理解”，随后只问一个关键问题，并在问题旁标注“会改变：近期路径与验证顺序”。
- 回答区是内容流中的 `SettingsCard` 式 composer：三条可选建议、自然语言输入、`不知道`、`回答并继续`。没有选择或输入时主按钮禁用语义。
- 回答后在原位置追加用户决定和烛龙确认，下一问题变为“最低可接受完成标准是什么”；顶部不换页。
- 固定 `300px Detail Rail` 是“活简报”：目标、用户决定、硬约束、烛龙假设、未决问题逐项展示；刚更新字段用 accent-soft，点击事件历史后原位替换。

### 需要验证

- 连续上下文是否让 grill 更像协作，而不是问卷。
- 会话流是否仍然足够克制，没有退化成聊天产品。
- 活简报能否让用户立即看见回答造成的结构变化。

## B — 活简报共创（Living Brief）

### 交互主张

规划简报不是对话结束后的摘要，而是用户与烛龙从第一轮开始共同维护的委托合同。问题只在某个字段无法成立时出现。

### 像素级结构

- 共同会话状态带显示“简报共创中”“v0.4”“2 个阻塞委托的缺口”。
- 主区是一张纵向原生文档卡，宽度占满可用主区；顶部有版本、变更数和“查看上一版”。
- 每个字段为 `92px label rail + 1fr field body`：目标、完成标准、硬约束、用户取舍、可自主事项、显式假设、未决问题。
- 用户原话使用普通白色 field；烛龙建议使用淡蓝 surface 与“烛龙提议” StatusPill；已确认项使用成功点；缺失项使用琥珀小点，不使用粗边线。
- 当前字段“第一条可用路径”展开为 inline patch：旧值为空，新值是烛龙建议，下面并排三个可改写选项和“采用这项修订”。
- 采用后字段立即变为“用户决定”，版本从 `v0.4` 升为 `v0.5`，顶部变更数更新；下一缺口“完成标准”在同一文档内展开。
- 右侧 Detail Rail 只检视当前字段：用户原话、已用事实、烛龙假设、备选表达、为什么建议、影响哪些后续计划。它不重复整场摘要。

### 需要验证

- 直接共同编辑委托边界是否比会话问答更有全局感和信任感。
- 字段结构是否帮助白盒，而不会退化为复杂表单。
- 用户能否自然理解“采用建议”“改写”和“保留未决”的差别。

## C — 有界委托运行（Delegated Run）

### 交互主张

烛龙应该替用户做可以自主完成的规划工作，只在目标、硬约束或关键取舍必须由用户决定时停下；运行过程必须可见、可暂停、可介入。

### 像素级结构

- 会话状态带显示“运行到决策门”“本轮可自主 3 项”“Todo 写入未授权”。
- 主区顶部是一条紧凑运行契约，列出当前目标、允许的数据、本轮自主事项和必须停下的条件。
- 主体是纵向运行线：每行 `26px 状态 glyph + 1fr 步骤／产物 + 90px 状态`。完成步骤折叠为一行；当前步骤展开；未开始步骤弱化。
- 代表运行步骤为：理解目标、核对本地事实、识别关键歧义、验证硬约束、形成阶段地图、生成近期草稿。
- 当前“识别关键歧义”展开为决策门，说明“烛龙不能替你决定第一条产品价值路径”；提供三项选择、自然语言补充和“确认并继续运行 1 步”。
- 确认后决策门变为完成记录，下一项“核对完成标准”开始；界面显示新产物、下一步和下一次会暂停的条件，不瞬间跳到最终草稿。
- Detail Rail 是本轮运行检视：实际输入、所用证据、显式假设、考虑过的备选动作、选择当前动作的理由、可使用权限、下一步和停机条件。

### 需要验证

- 用户是否真正感到烛龙在代为工作，而不是换页生成硬编码结果。
- 决策门能否减少无价值追问，同时保留用户最终取舍权。
- 运行线是否足够产品化，不像 CI 或开发者工具。

## 当时的比较方法

- 三个候选曾以独立状态运行，避免把一个候选中的回答伪装成另一个候选的结果。
- 每个候选均验证初始态、空回答 fail-closed，以及回答后“用户输入 → 状态变化 → 下一步变化”的可见传播。
- 这套比较设施已经完成使命，不是 R3 的产品能力或验收入口。
- `panel=events` 继续用 300px Detail Rail 原位展示事件历史。

## 当时的验证证据

- 三个初始态和三个推进后状态均在真实 Chrome 中运行过。
- CDP 验证过无回答不能推进、回答后状态可见变化、三个候选状态互不污染，以及当时的切换设施可用。
- 视觉验证覆盖 1320×820、1180×760、长内容底部可达、无水平溢出、Sidebar 240px 和 Detail Rail 300px。
- 这些结果只能支持候选选择，不能替代 R3 完整状态机的重新验证。

## 已确认结论

2026-07-10 用户确认采用组合方案：

- 委托前以 B“活简报共创”为唯一共同工作对象；
- 只有阻塞简报成立的关键缺口，才以内联方式使用 A 的单轮 grill；
- 用户审查并确认规划简报后，进入 C“有界委托运行”；
- 有界运行遇到目标、完成标准、硬约束、产品价值取舍或范围扩大时，必须停在决策门；
- 结构化计划成立后才派生 Todo 变更 diff。

A 的完整会话流不作为主布局，因为持续对话会稀释共同工作对象；B 单独使用不能充分表达委托后的 Agent 工作；C 不用于委托前，否则会在目标未成立时制造自动化错觉。

R3 已吸收这套组合结论。当前 runtime 只保留“活简报 → 内联 grill → 有界委托运行 → 结构化计划 → Todo diff”的单一路径；A／B／C 候选运行代码、候选 URL 参数、prototype controls 和键盘 switcher 均不再属于当前原型。
