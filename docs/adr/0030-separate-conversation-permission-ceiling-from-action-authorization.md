# ADR 0030：分离对话权限上限、会话数据授权与 Todo 行动授权

- 状态：已接受
- 日期：2026-07-24

## 背景

烛龙曾在每场新会话前展示只有“确认”按钮的阅读范围卡片，并把授权限制为一小时。它还以完整 Provider 配置身份作为重授权条件，因此显示名称、模型或能力声明变化也会打断对话。这个流程没有给用户真实选择，却让正常会话反复停在内部授权状态。

读取任务数据、向远程服务发送数据和修改 Todo 是三种不同风险。把它们压成同一张会话卡既不能表达长期偏好，也容易让一次读取确认被误解为写入许可。

## 决策

1. 设置提供两个独立权限上限：
   - 任务数据读取；
   - 远程发送。

   每项均为允许、询问或禁止，默认值为允许。任一适用项为禁止时整体禁止；否则任一适用项为询问时整体询问。Provider 在本机处理时不适用远程发送项。
2. 允许模式下，用户提交新会话即授权该入口固定且已披露的数据范围并直接开始响应。询问模式下，首次 Provider run 前展示“继续本次会话”和“暂不使用”；后者暂停会话并返回烛龙首页。禁止模式不得创建新会话、追加消息、建立规划委托或构造 Provider 请求。
   - 首次运行没有偏好记录时使用默认允许；偏好记录存在但无法完整解码时，任务数据读取与远程发送改为禁止，自动分类关闭，烛龙页面保留以便用户修复设置。
3. 会话数据授权绑定精确数据范围与 Provider 数据接收方，不设置时间到期。数据接收方由本地／远程性质和远程 endpoint 组成：
   - 数据范围扩大时重新确认；
   - 远程 endpoint 或本地／远程性质变化时重新确认；
   - 显示名称、模型、Provider 类型标签或能力声明变化不单独触发重新确认，但实际运行身份继续写入发送记录与产物溯源。
4. 会话页面和上下文 rail 持续披露数据范围、处理位置、远程 endpoint 与实际模型。透明披露是正常状态；只有询问模式的首次使用和实质边界变化才阻断。
5. Todo、复盘和分类写入继续使用各自的一次性行动授权，绑定用户看到的当前产物版本、精确 diff、来源快照和日期。读取或远程发送权限不能继承为写入权限。
6. 晷迹尚未发布，sidecar 采用 clean cut：从授权记录与当前 schema 中删除 `expiresAt`，不迁移或兼容开发期旧授权数据。

## 风险、回滚与监控

- 长期打开的会话可以在同一范围与接收方下继续读取更新后的任务内容。用户可以随时把任一权限改为禁止、暂停或删除会话；App 在 UI、消息入口和异步 Provider 请求边界重复 fail-closed 检查，避免设置改变后已有任务继续发送。
- endpoint 使用完整规范化 URL 比较，路径变化也视为接收方变化。这可能产生保守的额外确认，但不会静默放宽。
- 回滚时关闭烛龙旁路并保留普通 Todo；不得把读取授权降级为 Todo 写入许可，也不得恢复只有单一确认选项的卡片。未发布期回滚代码后必须重置开发数据并重新生成当前 schema。
- 本机监控只记录权限策略、阻断类别和 Provider 运行状态，不记录任务正文或凭证。

## 验证

- 领域测试验证授权不随时间过期、同一 endpoint 下改名或换模型不中断、改变 endpoint 必须重新授权，持久化重放仍验证精确范围与接收方。
- Runtime 测试验证允许／询问／禁止组合决策和设置持久化。
- 真实 Settings App E2E 通过 WindowServer 点击两个三态 segmented control，并验证 Store 收到询问与禁止。
- 真实烛龙对话 E2E 验证默认允许时首条回复直接流式出现；改变远程 endpoint 后同时出现继续与暂不使用；确认后可继续；重启时保持同一 endpoint 但改变模型不会再次出现卡片。
- 演示 fixture E2E 继续要求四场历史会话的非预期授权卡数量为零。
