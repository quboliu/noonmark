## 用户可见变化

- iCloud／Local Folder 同步改为 Local-first Replication V2：本机写入先由 SQLite authoritative store 原子提交，远端只承载 content-addressed immutable publication。
- 最近同步与最近有效同步只在对应 durable 事实成立后推进；等待 iCloud materialization、同步失败与 fork／conflict 以 typed state 呈现，不把“代码跑过”冒充成功。
- 同步期间普通本机修改不再因 transport wait 被拒绝；真正的本机 persistence failure 仍精确拒绝该次 mutation 并保留资料。
- iCloud writer 为 append-only，禁用 mutable head；应用没有删除、覆盖、替换、移动或改名远端对象的能力。

## 资料兼容

- SQLite：current schema 19。开发期 clean cut，只接受空库创建 schema 19或 exact schema 19；v15、v17、v18 在任何 WAL／DDL／DML 前 fail-closed，不迁移、不兼容、不自动删除。
- JSON：只导入 canonical format 7；format 6 与其他旧格式 fail-closed。
- 同步 repository：只接受空 repository 初始化或 exact Replication V2 marker／grammar。V1 与无 marker 非空目录 fail-closed；应用不迁移、不清理、不覆盖旧目录。
- 用户已审核上述不兼容边界。需要旧资料时只通过 current format 7 数据包重新导入；旧 iCloud 目录只能由用户自行处理，App 与测试不代为删除。

## 风险、回滚、灰度与监控

- 风险：schema 19 clean cut 会拒绝旧本机数据库与旧同步 repository；immutable publication、dual watermark 或 fork 处理错误可能导致等待、重复 apply 或同步停滞。
- 回滚：任一 trial 门禁或灰度失败即停止交付并退休当前 build；保留用户本机资料与全部 iCloud 对象，不自动降级、不恢复 V1、不删除或覆盖远端资料。下一候选使用更大 build。
- 灰度：完整本机 trial 门禁 → 第一台 Mac 手工使用 → 第二台实体 Mac 对等同步 → 连续 72 小时 soak → 另行审核 tag／push／GitHub Release。
- 监控：观察 pending／confirmed／applied、最近同步、最近有效同步、typed incident、收敛耗时与用户主动导出的有界诊断；不得记录任务正文、路径、账号、同步 payload、AI 内容或原始 Error。
