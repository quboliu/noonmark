# 任务分类采用独立深 Module 与显式主分类／标签模型

**Status**: Accepted

晷迹不再用 `Tag I / II / III` 同时表达分组与标签。新版任务分类采用一个可选 **主分类** 与零到多个对等 **标签**，由 `NoonmarkCore` 中独立的 `TaskClassificationModule` 负责规划、验证、原子应用、历史快照、来源追踪和分类生命周期；分类库不再属于 **应用偏好**，当前分类关系也不再嵌入整个 **任务链** 的同步记录。

Module 的外部 **Interface** 收敛为查询、准备计划和确认提交三个入口。直接操作、快速捕获、分类管理和烛龙批量建议都先形成带 revision、完整 diff、影响范围和 digest 的计划，再由用户确认后原子提交；SQLite 关系表继续作为事实源，分类 commit envelope 只承担原子同步、幂等和审计，不把系统改成完整 event sourcing。

**Consequences**

- 每条任务链最多一个当前主分类；标签是无序集合，没有产品语义数量上限。
- 日轨迹成为历史事实时，在同一领域事务中冻结当时主分类和标签；若同一轨迹在废弃后原地重新启用并再次历史化，则按生命周期事件追加快照，不能删除或覆盖旧事件。事实解释错误只能追加历史分类更正。
- 分类改名保留稳定身份和历史名称；曾产生任务关系历史的项只能归档或合并，从未使用项才允许硬删除。硬删除释放名称，但保留最小旧 ID tombstone，旧身份永不复活。
- 分类项、当前关系、历史快照、更正和变更记录成为独立持久化及同步实体；缺少依赖时 fail-closed，不能保存悬空引用。
- 烛龙的批量整理与普通建议只能生成分类候选或草稿；用户确认后的关系是普通用户确认关系，不赋予烛龙未来修改权。新任务自动归类是唯一例外，使用独立的受限 authority、持久工作与用户覆盖 fence，详见 ADR 0026。
- 本次换代采用 clean cut；上一代分类模型、schema、数据包与 UI 不进入当前实现，也不提供迁移 adapter。详见 ADR 0017。

**Rejected alternatives**

- 保留三个槽位并给 Tag I 补充说明：仍会把组织归属与对等标签混在隐藏顺序中。
- 为快速新增、详情、管理页和烛龙分别公开写接口：调用方便，但会让规范化、历史和原子规则沿多条路径漂移。
- 首版引入任意分类类型注册、完整事件投影和向量时钟：表达力更强，但超出当前两个稳定领域类型，并与关系事实源 ADR 的取向冲突。
