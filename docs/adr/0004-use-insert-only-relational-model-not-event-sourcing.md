# 使用不可覆盖关系模型而不是完整事件溯源

晷迹第一期不采用完整 event sourcing，也不建立“事件日志作为唯一事实源 + 投影视图”的架构。经过本地 Claude rebuttal 后，决定用 Swift 领域层配合 SQLite/GRDB 的不可覆盖关系模型表达核心事实：任务链、任务定义、日轨迹、Day、子任务和每日复盘直接作为事实表存在，通过领域服务、数据库约束、触发器和唯一索引禁止删除、覆盖和多活跃轨迹。

**Consequences**

- 核心视图（Day Todo、任务池、未来计划、未完成池、已完成池）优先通过 SQL view / query 派生，不引入投影器。
- 已完成池每条完成记录需要展示开始日期、延续日期列表和完成日期；这些 **已完成轨迹摘要** 从同一任务链的 `day_traces` 派生，不新增可编辑事实表。
- 子任务使用 `lineage_id` 串联跨日延续记录，但不升级为独立任务链；子任务轨迹摘要从 `subtasks` 与 `day_traces` 派生。
- 可选的 change journal 只能作为未来同步和诊断的辅助流水，不是事实来源，第一期功能不得依赖它。
- 数据包第一期优先导出平台无关的状态快照，而不是必须回放的事件流。
