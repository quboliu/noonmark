# Mac UI 原型作为实现契约

**Status**: Accepted

Claude Design 在 2026-07-05 产出的 Mac UI 原型是晷迹 Mac 端第一版的硬标准。实现不得遗漏原型中的页面、控件、状态、交互、文案和数据含义。

**Context**

原型已归档到 `docs/design/prototypes/claude-mac-ui-2026-07-05/`。原型体现了产品最新要求，包括 Day Todo、任务池、未来计划、未完成池、已完成池、日历、设置、右侧详情栏、每日复盘、任务轨迹、描述、附言、手动进度、子任务权重、加权子任务进度、窗口尺寸、颜色语义、日期 strip 动效和撤销约束。

这些内容不只是视觉建议。其中“描述/附言”“手动进度”“子任务权重”“进度下限”“日历轨迹总览”等要求需要后端领域模型支撑。

**Decision**

- 原型文件作为设计证据归档，生产 SwiftUI 不直接依赖 HTML/JS。
- 新增 `docs/design/mac-ui-design-contract.md`，把原型拆成可验收的设计契约。
- 新增 `SuntraceMacUIContract`，把页面、控件、窗口尺寸、颜色 token、动效、详情栏状态、操作、弹窗和后端能力做成可测试契约。
- 后续 SwiftUI 实现必须逐项满足设计契约，不允许暗改或省略。
- 当设计契约与当前后端不一致时，优先补后端领域模型和 ADR，而不是降级 UI。
- `SuntraceCore` 支持任务描述、任务附言、手动完成进度、子任务难度权重、加权子任务进度、进度下限、日历日汇总、已完成子任务记录和设置偏好。
- `SuntraceCore` 的变更语义跟随原型：旧日轨迹标注已变更，通过变更指针指向新日轨迹，新任务开启新的任务链并出现在同一天。
- `SuntraceStorage` 必须同步支持上述字段和聚合视图，任务池 view 必须包含已回池任务链。

**Consequences**

- UI 验收必须同时检查视觉、交互和领域语义。
- 设计原型中的所有入口和状态都要有实现映射，即使某些入口第一期只是预留，也必须在 UI 中呈现。
- 后端模型不能只满足旧规格；必须跟随 Mac UI 契约补齐字段和派生视图。
- 设置页的同步入口第一期是同步端点占位，必须显示规划中，不能伪装成已可用同步。
- Linux 环境不能运行 SwiftUI 截图验收，Mac 端接入后必须补充真实 macOS 运行验证。

**Alternatives Considered**

只把原型当视觉参考：会导致进度、附言、日历和设置入口被实现成可选项，违背最新产品要求。

直接把 HTML 原型嵌入生产：短期快，但会绕开 SwiftUI 路线，也无法自然接入本地优先数据模型。
