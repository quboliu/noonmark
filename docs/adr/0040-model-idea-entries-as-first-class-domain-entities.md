# ADR 0040：想法条目作为一等领域实体

## 状态

已接受。

## 情境

晷迹新增对标 flomo／Memos／Thino 的原生想法记录能力：用户需要把尚未决定是否或如何执行的零散灵感、记录或提醒立即写下来，稍后再决定去向。这个需求与两个既有入口都相邻但语义不同：**任务附言** 必须依附某条任务链或日轨迹，且会随排期被快照进日轨迹、进入任务历史纪律；**快速捕获** 保存即形成任务，落点直接是 Day Todo 或任务池。

候选实现路径有三条：扩展任务附言以允许“不依附任务的附言”、以无日期普通任务承载想法、或建立独立的一等领域实体。前两条都会让不打算执行的文字进入任务状态机、池化视图、统计和日轨迹纪律，污染“任务即承诺”的领域语义。

## 决策

1. 想法记录由独立一等领域实体 **想法条目**（`IdeaEntry`）承载：`id: IdeaID`、归一化非空 `body`、可选 `categoryID: TaskCategoryID?`、`labelIDs: [TaskLabelID]`、`createdAt`／`updatedAt`、`deletedAt`。不扩展任务附言，也不以无日期任务冒充想法。
2. 删除只追加 `deletedAt` 墓碑，与任务附言条目同纪律；身份不能复用，也不能被离线或旧同步副本复活。
3. 分类复用现有任务分组与标签目录（`TaskCategoryID`／`TaskLabelID`），不建立第二套分类库；想法分类只是当前关系，不形成历史分类快照，也不参与分类关系历史的任务语义。
4. 引擎提供 `appendIdea`／`editIdea`／`deleteIdea`／`setIdeaClassification` 命令与 `ideaTimeline` 投影（创建时间倒序、按自然日分组、substring 过滤）；投影是查询结果，不是独立事实。
5. SQLite 新增 `idea_entries` 表，schema version 15→16；项目尚未发布并执行开发数据 clean cut，不提供迁移或旧 schema 兼容读路。
6. 想法条目纳入 `change_journal`、`SyncSnapshotDiffer` 与上下行协调器，与任务实体同等同步待遇；墓碑随同步传播，防止跨设备复活。
7. UI 采用双入口：侧边栏新页面「想法 / Ideas」（顶部常驻速记框 + 过滤框 + 倒序时间线 + 行内编辑与溢出菜单），以及全局快捷键速记浮窗（默认 ⌃⇧I，可在设置改键；沿用 ADR 0033 的非独占 Carbon hotkey、物理 virtual key 与冲突检查纪律）。两条入口写入同一领域命令，复用与任务快速输入相同的 `#标签`／`@分组` token 解析。
8. 想法记录不经过烛龙会话或 AI Provider，无 Provider 时全功能可用。第二阶段的想法→todo／排期与想法归类只完成设计（见 `docs/product/idea-capture-spec.md`），本次不落代码；届时转换走 ADR 0028 的对话产物通道与一次性确认，AI 未经确认不写任何数据的硬边界不变。

## 影响

- 优点：不打算执行的文字不再进入任务状态机、任务池、统计和日轨迹纪律，“任务即承诺”语义保持完整。
- 优点：想法与任务共享同一套分组／标签目录和 token 语法，用户不需要维护两套组织体系，第二阶段 agent 归类也能直接复用现有目录与 prompt 契约。
- 优点：墓碑删除加同步纳管让想法条目在跨设备、离线乱序场景下与任务实体行为一致，不引入新的复活面。
- 代价：领域、存储、同步和 UI 各增加一个实体面；想法与附言在语义上相近，必须靠 CONTEXT.md 词汇和 UI 入口持续说明边界，避免用户把想法当成“无任务的附言”或把附言当成随手记。
- 代价：schema version 前进一位，旧开发数据库按 clean cut 纪律直接作废。

## 风险与回滚

- 风险：想法条目与任务附言边界被用户或后续实现混淆。CONTEXT.md 已固化两者与快速捕获的三方边界，UI 上想法只出现在「想法 / Ideas」页面与速记浮窗，不投影到任何任务列表。
- 风险：同步乱序或并发时墓碑与编辑的竞争。编辑与删除按既有 change journal 纪律处理，墓碑防复活由同步合并层保证，并有乱序／并发测试覆盖。
- 项目尚未发布并执行开发数据 clean cut，不迁移旧库。回滚只能回到前一提交并执行 `scripts/reset-dev-data`，不得让旧二进制读取新开发数据。

## 验证

- `NoonmarkCoreTests` 覆盖正文归一化、空正文拒绝、编辑、墓碑删除、归类设置与时间线投影的倒序、自然日分组和 substring 过滤。
- `NoonmarkStorageTests` 覆盖 `idea_entries` schema、round-trip 与墓碑持久化；非当前 schema fail-closed。
- 同步测试覆盖想法条目上行、下行、乱序到达与删除墓碑不复活。
- 真实 `.app` E2E 覆盖「想法 / Ideas」页面的速记保存（Cmd+Enter）、`#标签`／`@分组` token、过滤、行内编辑、删除，以及全局热键浮窗的打开、Enter 保存、Esc 关闭与焦点恢复；SQLite 探针验证落库与墓碑。
- 完整 `scripts/test-e2e`、`make check` 与 DMG 安装测试继续作为发布门禁。

## 后续补充（2026-08-03）

第一阶段交付时补记以下语义决定，原决策条目不变：

1. 置顶是想法条目的当前状态而非历史事实：`pinnedAt` 记录置顶时间，先置顶者排前；删除形成墓碑时同步清除 `pinnedAt`，恢复不复活旧置顶。置顶只改变 `pinnedIdeas` 与时间线投影呈现，不产生新的事实类型。
2. 删除时正文归一化清空，墓碑不保留正文：回收站投影 `ideaTrash()` 只承载身份、分类与时间戳，恢复必须经 `restoreIdea(id:body:now:)` 由用户重新输入非空正文。这让已删除正文不再随同步 payload 与数据包继续流动，收敛已删除内容的暴露面。
3. 不提供硬删除：跨设备同步收敛依赖墓碑在缺少完整设备确认前持续存在，硬删除会让旧副本在乱序到达时复活。
4. `IdeaTimelineFilter`（正文 substring、`categoryID`、`labelID` 的 AND 组合）是投影查询参数；卡片上的分组／标签点击只把该分类写入当前过滤条件，不形成任何事实。
5. 存储侧 `idea_entries` 追加 `pinned_at` 列，schema version 16→17，沿用 clean-cut 无迁移纪律；`pinnedAt` 随同步 payload 与 **数据包** 流动。
