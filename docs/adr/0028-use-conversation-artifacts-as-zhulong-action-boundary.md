# ADR 0028：以对话产物作为烛龙的行动边界

- 状态：已接受
- 日期：2026-07-24

## 背景

烛龙原本把普通任务规划实现成固定链条：用户先进入规划流程，再填写规划简报、确认评审、授予单次委派、等待规划产物、发布 Todo diff，最后再次确认应用。这个模型保留了审计边界，却把内部账本步骤直接变成用户流程，造成对话冗长、行为机械，也无法在用户说出一个完整需求后直接展示“一个父任务加三个子任务”这种可编辑结果。

同一个问题也出现在复盘等产物上：自然语言对话与结构化确认控件是两套入口，用户必须主动从消息菜单切换流程。新增其他能力时若继续复制这套入口，会形成更多互不一致的固定工作流。

## 决策

1. 普通烛龙会话以自然对话为默认交互。只有缺少会实质改变结果的关键信息时才追问，不要求依序经过规划简报、评审或委派。
2. Provider 可以在自然语言回复后附带严格验证的 `conversation-artifact.v2` 产物信封。协议区块不进入聊天正文；半截、未知或不符合 schema 的产物 fail-closed。
   - 若回复已经表达产物意图但信封格式无法验证，adapter 可以在同一次授权 Provider run 内把原回复交回同一 Provider，执行至多一次纯格式修复；修复提示不得扩大授权数据、改变任务语义或取得写入权限。
   - 修复结果必须重新通过完整信封与字段 schema。修复请求失败、仍不合法或没有结构化产物时，原 Provider run 继续 fail-closed；不得无限重试，也不得从自然语言猜测任务执行。
3. 第一批产物类型为：
   - `taskPlan`：包含一个或多个父任务、描述、附言、任务池／今天／未来日期落点，以及每个父任务的子任务与难度。
   - `dailyReview`：包含今日总结与明日提醒。
4. `taskPlan` 投影为对话内任务草稿卡。用户可以直接编辑、增删父任务与子任务、修改落点，也可以继续对话要求烛龙返回完整修订版本。
5. 用户点击“提交任务”或发送语义明确的“提交”消息，均绑定当前可见草稿版本，走同一套 Todo diff 一次性授权与原子应用路径。讨论、疑问和否定语句不构成授权。
6. Provider 回复、原始产物、用户修订、一次性授权和应用回执继续保存在加密 sidecar 账本。有效内联编辑经短暂防抖形成修订版本，离开会话前立即刷盘；刷盘失败时本次运行内保留编辑并阻止会话内离开操作。新产物会取代旧产物成为当前草稿，最新版本成功提交后父版本不得重新浮现。
7. 聊天投影只显示自然消息、可编辑产物、真实错误、失效和当前必须处理的授权边界。Provider run、草稿发布和成功应用等正常内部事件留在事件历史，不作为聊天流程进度。
   - Provider 失败必须区分传输／服务失败与对话产物验证失败；不得把产物 schema 错误误报成配置错误。两类失败都必须明确说明没有写入任务或复盘。
8. 深度规划、复盘及后续结构化能力遵循同一交互原则：自然对话后投影专用的可编辑产物，再以一次明确提交应用。旧规划简报与规划委派领域记录只为既有 sidecar 兼容和审计保留，不再形成另一套用户可见流程或运行 fallback。

## 后果

- 用户可以在一轮自然对话后直接看见任务的真实形态，并在写入前完成编辑。
- 任务池、Day Todo 与未来计划使用同一个任务产物模型；差异只由每个父任务的落点表达，不复制三套提交逻辑。
- 每日复盘复用同一产物信封与“编辑后一次提交”交互原则，后续结构化能力也应新增产物类型，而不是新增固定会话流程。
- Todo 写入安全性不降低：聊天文本不能直接执行，结构化产物必须验证，提交仍绑定当前快照与精确 diff，并在普通领域接口内原子应用。
- 旧规划领域类型可以暂时保留给既有 sidecar 审计与历史测试，但其用户可见固定入口、消息右键流程和普通成功事件投影必须删除。

## 被否决的替代方案

- 保留旧流程，只缩短文案：无法解决重复确认和双入口问题。
- 从自然语言正文猜测任务并直接写入：不可验证，也无法精确绑定用户看到的版本。
- 每个子任务逐项确认：破坏父子结构，也让批量规划变成高摩擦表单。
- Provider 返回后自动写入：绕过用户编辑与一次性授权边界。

## 验证

- 单元测试验证普通回复、任务方案、每日复盘、非法 schema、流式协议隐藏、用户修订及旧版本不回退。
- Provider adapter 测试验证自然语言正文与产物分离，并验证无效流式信封只修复一次、修复后重新执行完整 schema 校验。
- 手动 DeepSeek live smoke 覆盖真实流式 adapter、Provider run、任务 diff、加密 sidecar 保存与恢复；该外部测试不进入默认门禁。
- 加密 sidecar 测试验证 Provider 原版与用户修订可往返恢复。
- 当前快速迭代的真实 `.app` E2E 验证三种落点与父子任务草稿卡出现、真实按钮可点击、一次提交生成回执，并通过持久化引擎查询确认任务分别进入任务池、Day Todo 与未来计划。
- 功能点敲定后的最终门禁补齐物理内联编辑、明确文字提交、重启后目标页面可见性与四种对话投影回归。
- 真实 App 截图验证协议数据和内部 Todo diff 发布事件不进入聊天正文。
