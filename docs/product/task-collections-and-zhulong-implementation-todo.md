### 不得回退的产品决策

- “双轨编织流”只是旧的可选视图，不等于用户要求的默认普通对话页。
- 默认对话必须是单列、连续时间流和底部 Composer；不得套用卷宗、章节、双轨、dashboard 或多卡片外壳。
- 旧三视图允许保留自己的视觉语言，但任何旧视觉容器不得进入默认对话 renderer。
- 烛龙首页／会话入口页维持既有布局和信息架构；本轮重构只作用于进入会话后的交互页，不能把首页改造成聊天页。
- 分组是否彩色由用户认可事实决定，不得根据“是否由 AI 使用过”、颜色是否存在或名称样式推断。
- 本轮必须交付真实 `.app`；只通过单元测试、只生成截图或只报告源码完成都不算完成。

## 4. 烛龙、自动分类／标签与 Provider 独立开关

- [ ] Provider 开关只控制该 Provider 是否可执行远程请求。
- [ ] 烛龙页面开关只控制导航和会话入口可见性。
- [ ] 自动分类／标签开关只控制新任务自动归类能力。
- [ ] 关闭烛龙页面不得关闭自动分类／标签。
- [ ] 关闭自动分类／标签不得隐藏烛龙页面。
- [ ] 关闭任一功能不得删除 Provider 凭证、历史分类、目录或烛龙会话。
- [ ] 关闭烛龙页面时，若当前正在该页则安全回退到可见页面。
- [ ] 关闭自动分类时停止新任务入队并停止 worker 调度。
- [ ] worker 领取和最终提交前都重新检查开关，防止关闭后的竞态提交。
- [ ] 重新开启后默认只处理此后新任务；旧任务继续使用既有 backlog 决策。
- [ ] 三个开关分别持久化并提供独立可访问性标识。
- [ ] 设置页用简洁层级解释三个能力边界，不堆叠卡片。
- [ ] 用真实 App 验证全部开关组合、重启保持、导航变化和作业数据库状态。

- [ ] Composer 固定在对话底部，滚动长流时保持可用。
- [ ] Composer 支持追加指令、发送和停止／运行状态所需控制。
- [ ] 用户决定、数据范围、规划委托和 Todo 写入继续分别确认。
- [ ] Todo diff、计划草稿、证据、范围和事件历史可从对应消息打开右侧检视面。
- [ ] 关闭右侧检视面后可从来源消息重新打开。
- [ ] 验证既有烛龙首页保持不变；默认对话的视觉重构仅在进入会话后生效。
- [ ] 默认对话不出现旧视图的状态带、轨道标题、卷宗脊柱或章节编号。
