# 烛龙 sidecar 数据采用应用层静态加密

烛龙记忆、行为画像、会话、规划草稿、事件历史、校准上下文和 Provider 发送正文比普通任务事实包含更集中的敏感信息，因此默认只留本机仍不足够。晷迹使用 Keychain 中的应用独立密钥加密 sidecar 数据；加密能力不可用时烛龙 fail-closed，普通 Todo 不受影响。

**Consequences**

- sidecar 数据库、日志、搜索索引和崩溃报告不能留下敏感明文副本。
- 不复用 Provider API Key 或同步凭证作为数据密钥。
- Keychain 密钥丢失时不回退明文；sidecar 可以不可恢复，但核心任务事实必须继续可用。
- 普通 Todo 数据包和同步仍不包含 sidecar；未来导出使用独立用户密码加密包，不复制本机密钥。
- 晷迹尚未发布且没有用户数据，烛龙会话 sidecar 只定义一种 canonical current envelope；当前由 ADR 0030 升为 format version 2，并直接拒绝 version 1。只接受最新完整 schema，不保留旧 record、decoder、converter、旧 AAD fallback 或迁移分支。
- 非当前 envelope、缺失必填字段或存在未知顶层字段时一律 fail-closed，由开发者显式清理可重新生成的测试 sidecar；App 不推断、补齐或自动升级格式。
- 测试数据只由当前领域行为生成，只验证当前格式 round-trip、当前 schema 完整性及拒绝损坏或非当前 envelope。
- 存储、搜索、备份和恢复设计必须验证加密边界及 fail-closed 行为。

## 风险评估

- Keychain 密钥遗失、损坏或被用户主动清除后，既有 sidecar 不可恢复；系统必须明确报告，不能尝试明文读取或生成替代密钥覆盖证据。
- 应用在 Provider 请求或原子文件替换期间退出，可能留下已加密但尚未结算的运行记录；启动恢复必须把它结算为可审查的中断失败，不能自动重发。
- 文件名、目录权限和错误日志仍可能泄漏存在性或会话数量；sidecar 目录固定为 `0700`、文件固定为 `0600`，日志不得包含正文或密钥材料。
- 多执行面并发写入可能造成旧状态覆盖；第一阶段只允许单一 App actor 编排同一会话，未来多进程访问前必须增加跨进程 CAS 或锁定协议。

## 回滚方案

- 可关闭新烛龙入口和 Provider 调用，但保留 Keychain 密钥及加密 sidecar，避免回滚本身造成数据遗失。
- 回滚不能恢复旧固定模板、写入明文或把 sidecar 合并进普通 Todo 数据；普通 Todo 继续独立运行。
- 若新格式无法安全读取，保持 fail-closed，并允许用户整体删除不可恢复的烛龙 sidecar；不得影响核心任务数据库。

## 灰度策略

1. 先以独立 `NoonmarkZhulong` 模块和临时目录完成错误密钥、篡改、权限、重启与真实 Keychain 测试。
2. 再接入内部 App 会话路径；用户主动提交新会话后，按设置中的对话权限上限决定直接开始或首次询问，并持续披露数据范围与实际接收方；范围扩大或接收方改变时仍重新确认，且绝不自动写 Todo。该授权边界与无时间到期语义由 ADR 0030 更新。
3. Provider live smoke、真实 `.app` E2E、持久化探针和 DMG 安装启动全部通过后，才允许 clean-sheet 一次性 cutover。

## 监控方案

- 只在本机记录分类后的 Keychain 失败、解密失败、恢复拒绝、Provider 中断和原子写入失败次数，不记录请求、响应、路径中的用户内容或密钥。
- App 事件面板展示用户可读失败摘要及对应会话入口；详细请求与响应只存在加密发送记录。
- 发布验收持续扫描 sidecar、普通日志、崩溃报告和导出包，确认不存在已知敏感测试标记的明文字节。
