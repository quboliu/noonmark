# 当前任务组织与完成历史分离

**Status**: Accepted  
**Date**: 2026-07-26  
**Risk**: A 级——跨状态分类编辑、完成池投影与父子任务选择路径

## Context

任务链已经分别保存当前主分类／标签关系和日轨迹分类快照，但界面曾把已完成、未完成与已废弃详情误当成整体只读，导致用户无法继续整理任务。已完成池又把父任务和已完成子任务平铺成互不相干的记录，只用“子任务”和“属于……”补充文字关系；这既重复父任务信息，也无法表达子任务完成逐日累积、最终汇入父任务完成的过程。

当前日的完成仍可撤销，只有日结束后才成为锁定历史。分类编辑不能改变这条既有时间边界，也不能以修改当前组织信息为由覆盖已经冻结的执行事实。

## Decision

1. 主分类和标签继续属于任务链的当前组织关系。无论任务当前位于 Day Todo、任务池、未来计划、未完成池或已完成池，详情都使用同一分类编辑器；修改结果立即影响当前列表分组与徽标。
2. 已锁定日轨迹的主分类和标签快照保持不可覆盖。编辑当前关系只新增普通分类关系事实，不改写快照；当天可撤销的完成仍在日结束时才按最终当前关系冻结。
3. 已完成池从现有日轨迹和子任务事实派生 `CompletedTaskHierarchy`，不新增持久化表。每条任务链只显示一个父任务入口，并按子任务轨迹身份去重、稳定排序，只纳入已经完成的子任务。
4. 父任务尚未完成时，父行使用待完成状态，已完成子任务缩进并保留完成勾；未完成子任务不出现。父任务完成后，父行承担唯一强完成状态，子任务改为低强调短横线。
5. 未完成池继续只用父任务作为列表条目，不把子任务完成明细展开成第二套层级；历史日轨迹仍可从既有明细入口查看。

## Consequences

- 用户可在任何任务状态下整理分组与标签，列表会反映最新组织方式。
- 历史分类审计和当前列表组织可能不同；这是“当时事实”与“现在如何整理”的明确分离，不是数据漂移。
- 已完成池不再把子任务作为与父任务同级的独立记录，排序与键盘选择都以父任务层级为单位，再进入其可见已完成子任务。
- 当天完成后修改分类并撤销完成，不会提前生成历史快照；锁日后再修改分类则不会覆盖已经冻结的快照。

## Verification

- Core 测试覆盖锁日后的当前分类修改与历史快照不变，以及父任务未完成／完成两种层级投影。
- Mac UI 契约验证跨状态分类编辑、只显示已完成子任务及父任务完成后的低强调子行。
- 真实 App E2E 从已完成层级、未完成池分别打开详情修改标签，检查可见父子结构、重启回读与 SQLite 历史快照。
- 交互式演示同时提供一个部分完成父任务和一个完整完成父任务。
