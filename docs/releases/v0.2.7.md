## 用户可见变化

- 修复同步上传确认后没有同时推进本机 producer frontier 的问题。App 不再把刚上传的本机完整基线当成远端新资料反复下载、merge 和 audit。

- confirmed upload 的 journal 状态与 frontier 由同一个 SQLite transaction 原子提交；receipt、sequence、hash 或 frontier 不一致时整体 rollback，不会留下半提交状态。

- SQLite：继续使用 schema v18；从 `0.2.6 (28)` 升级没有 schema 变化。
- 同步 repository：格式不变；不新增迁移、兼容层、自动删除或回退路径。foreign producer 资料仍走普通 pull，只有精确匹配的本机 confirmed immutable batch 才能推进 frontier。

- 灰度：只把独立命名的 build 29 DMG 交给当前指定用户手工安装和启动；不建立 tag、不 push、不发布 GitHub Release。
- 监控：确认「最近同步」与「最近有效同步」不再为「暂无」，等待上传能自然收口；若再次长时间同步或出现失败，保留本机资料并由用户主动导出新的有界诊断包。
