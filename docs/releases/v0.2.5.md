# v0.2.5（build 23）候选发行记录

- 发行 commit：待候选提交完成后回填
- GitHub Release：待受保护 tag 验证完成后回填
- DMG SHA-256：待 CI 分发正本完成后回填

## 用户可见变化

- 本地目录与 iCloud Drive 同步改为依据持久 frontier 分页取得未见 immutable batch；稳态同步不再以全量历史 mirror 作为读取或上传路径。
- 对分段 hash 链增加分页边界完整性校验；损坏的非尾端 batch 不会因页边界而被接受。
- 同步锁诊断闭环现在以真实任务变更触发上传，再验证锁等待、修改拒绝、异常终止、重启与用户主动导出。

## 资料兼容

- SQLite：当前 schema v18。受控 v15／v17 升级保留领域事实与设备身份，但会 clean cut 旧 journal 与 sync metadata；新同步协调器从本机 snapshot 重建 baseline。
- 同步 repository：这是未公开格式的 clean cut。升级前用户须清空既有 iCloud repository；新版本不会混读旧 repository。agent 不读取、探测或清理 production 资料。
- JSON：严格 canonical v6 数据包继续可导入；当前导出格式仍为 v7。

## 验证摘要

- fast gate：待候选 commit 的 `make check` 回填。
- symptom gate：待候选 commit 的 128／256 历史增量同步、真实 Local Folder transport 完整性和隔离真实 App E2E 回填。
- release gate：待本地 Apple Development DMG 静态／安装验证与 GitHub-hosted 精确 commit CI 回填。

## 灰度、监控与回滚

- 灰度：先由指定私下用户安装；首次同步前清空旧 iCloud repository，再让新版本从本机 snapshot 建立新 baseline。
- 监控：只检查有界、强类型的同步 operation／incident、frontier、lock wait 与导出诊断容量；不上传诊断或用户内容。
- 回滚：停止候选 Release；若改回 v0.2.4，仍须清空同一 repository 后重建，不得混读两种同步格式。保留用户本机资料，禁止自动删除、迁移或降级 production 数据。
