# Todo清单产品调研

调研日期：2026-07-05  
调研对象：[Todo清单官网](https://todo.evestudio.cn/)、[Todo清单学院](https://www.evetech.top/)、“Todo清单”应用公开资料  
调研目的：理解 Todo清单的核心功能、核心理念，并提炼对晷迹（suntrace）的产品启发。

## 结论摘要

Todo清单不是单纯的待办事项记录工具，而是一个围绕「计划清单 → 专注执行 → 数据复盘」闭环设计的个人时间管理产品。它的核心方法论来自 Ivy Lee 时间管理法，产品层面再叠加 GTD、番茄工作法、数据统计和跨平台同步。

它最有价值的产品主张是克制：不鼓励用户花大量时间装饰清单、堆叠复杂日程，而是让用户把长期任务拆到今天，按重要顺序推进，完成后通过数据复盘获得反馈。

对晷迹的直接启发是：MVP 不应先做大而全的任务管理系统，而应先抓住「今天要做什么、先做哪一个、如何开始、完成后如何复盘」这一条主路径。

## 产品定位

官方将 Todo清单定义为一款跨平台 GTD 待办事项与番茄专注软件。它强调三个关键词：

- 待办事项：记录、分类、排序、提醒、完成。
- 时间管理：今天 / 明天安排、日程概览、重复事件、日历协同。
- 专注与成长：番茄专注、白噪音、专注记录、数据复盘。

官网把产品描述为跨平台待办事项与时间管理应用，支持 Android、iPhone、Windows、Mac、iPad、Apple Watch、华为鸿蒙手表、荣耀手表、OPPO 手表、三星手表等平台。公开渠道显示的版本号不完全一致：官网列出 Android v4.2.7、Windows / Mac v3.11.2；应用宝页面列出 Android v4.4.6；App Store 页面列出 3.93（2026-06-03）。这说明不同渠道资料更新节奏不一致，产品调研时不能只看一个页面。

## 核心理念

### 1. 专注今天，聚焦当下

Todo清单最核心的理念是把用户从复杂计划中拉回「今天」。官方方法论页面认为，待办计划和实际完成之间存在较大偏差，过多延误会让用户对清单产生抗拒。因此产品主张用更少步骤安排事项，用更清晰的今日待办推动执行。

这不是普通的“创建任务后等提醒”逻辑，而是鼓励用户每天面对有限任务，按重要性排序，然后逐项推进。

### 2. Ivy Lee 优先于复杂任务体系

Todo清单把 Ivy Lee 时间管理法产品化：列出重要事项、按重要性排序、从第一项开始做、一次只处理一个问题、每天循环。

对应到产品设计上，它没有把四象限、复杂优先级、时间段排程作为核心，而是用拖拽顺序表达重要性，用 Day Todo 视图承载今天任务，用任务拆分降低执行难度。

### 3. 克制配置，把时间还给执行

设计理念页明确表达：高效且长久的时间管理不是花大量时间配置和装扮 TodoList。这个判断直接影响了它的功能取舍：

- 不做时间段功能，避免用户把日程排得过满。
- 不做四象限功能，避免把产品变成大而全的方法论集合。
- 番茄钟不做正计时和暂停，保持与番茄工作法一致。
- 通过系统日历协同提醒，而不是让应用长期后台运行。

这里的底层哲学是：工具应该降低心理负担，而不是创造新的维护成本。

### 4. 从计划到执行再到复盘

Todo清单的闭环是：

1. 计划清单：分类、今天 / 明天、无日期、排序、工作量。
2. 专注执行：番茄钟、白噪音、沉浸模式、完成勾选。
3. 数据复盘：昨日小结、事件统计、番茄统计、周报、趋势。

这个闭环让它区别于只负责“保存任务”的清单应用。它试图让用户形成持续反馈：今天安排是否过量、哪类任务常拖延、专注时间分布如何、工作量趋势是否稳定。

## 核心功能地图

### 1. 事件创建与整理

核心能力：

- 快速添加：在 Day Todo 页面点击加号，输入事件名称即可创建。
- 日期设置：支持今天、明天、暂无日期、选择日期。
- 时间设置：支持时间选择和提醒时间。
- 重复设置：支持每天、每周等重复规则。
- 子任务：用于拆解复杂或长周期事件。
- 工作量标记：用一般、中等难度、较高难度表达任务强度。
- 图片附件：支持相册导入或拍摄。
- 拖拽排序：通过上下拖拽调整重要性顺序。
- 灵感便贴：保存临时想法，也可浏览随机公开便贴。

产品含义：

- 它把“任务”建模成可执行单元，而不是只存一行文本。
- 工作量、子任务、图片、重复、提醒这些字段服务于执行和复盘。
- “暂无日期”相当于待办箱，承接未来可能做但尚未排期的任务。

### 2. Day Todo 与日程视图

核心能力：

- Day Todo：承载每日待办，是产品主工作台。
- 最近待办：查看近期未完成和未来几天事件。
- 分类清单：按工作、生活、学习等主题组织任务。
- 日历视图：以月为单位查看清单安排。
- 日程概览：支持条目背景色、完成删除线、仅显示未完成、剩余量等设置。
- 周视图 / 月视图：帮助用户从不同时间尺度查看安排。

产品含义：

- Day Todo 是“今天执行”的入口，日历和概览是“计划理解”的入口。
- 它不是完全拒绝未来计划，而是把未来计划收束为辅助视图，不让它压过今日执行。

### 3. 事件管理

核心能力：

- 订阅系统日历，系统日历事件可同步到 Day Todo。
- 重复事件管理，支持批量删除、批量修改或单独修改。
- 事件设置，包括周视图进度、月视图标记、星期开始日、订阅日历等。
- 语音快速添加，支持日期自然语义识别。
- 事件列表设置，包括勾选框颜色、完成删除线、顺序数字、事件描述、子事件进度。
- 搜索待办。
- 分享清单，支持图片或文本形式。

产品含义：

- Todo清单很重视“任务进入系统”的低摩擦，语音和自然语义识别就是为了减少录入成本。
- 批量管理重复事件和搜索能力说明它已经覆盖重度用户场景。

### 4. 番茄专注

核心能力：

- 开始专注：从番茄专注页面启动。
- 专注记录：保存完整和不完整番茄钟的事件名称与时间。
- 白噪音：专注时播放环境音。
- 沉浸模式：强化专注界面。
- 番茄钟设置：番茄时长、休息时长、屏幕常亮、推送通知、完成提示音、悬浮窗等。
- 番茄统计：统计番茄专注数据。

产品含义：

- 番茄不是外挂计时器，而是连接任务执行和数据复盘的中间层。
- 不完整番茄也记录，说明它关注真实行为，而不只是成功完成的理想状态。

### 5. 数据复盘

核心能力：

- 昨日小结：昨日事件工作量、昨日番茄专注时长、近七天工作量趋势、昨日番茄专注时间分布。
- 事件统计：工作量趋势、事件完成率、拖延趋势、周几最勤奋、时间掌控评估、历史累计达成事件数。
- 番茄统计：专注时长趋势、最佳专注日、专注时间分布、累计番茄数。
- 周报：上周达成数、工作量、工作量趋势、番茄收成、专注时长趋势、最佳工作日。
- 热力图：通过小组件和版本记录可见，工作量热力图是它的数据表达之一。

产品含义：

- 数据复盘是 Todo清单的差异化重点之一。
- 它把“完成了多少”扩展成“如何完成、何时完成、是否拖延、工作量是否稳定”。
- 对长期自我管理而言，复盘比任务列表本身更容易形成留存。

### 6. 跨平台与同步

核心能力：

- 待办事件和番茄数据云端加密保存。
- 换设备后可同步。
- 高级账户支持最多 10 个设备同时使用。
- 移动端可免费使用，高级账户解锁无限容量云同步、跨平台支持等能力。
- 同一账号开通高级账户后，全平台通用。

产品含义：

- “跨平台”不是附加卖点，而是时间管理产品的基础体验：用户在手机记录、电脑执行、手表提醒之间切换。
- 高级账户将同步、容量和跨端能力作为主要商业化承载。

### 7. 小组件与外部入口

核心能力：

- 桌面小组件：事件列表、日历 + 任务、周视图、月视图、工作量热力图、倒数日、番茄专注。
- 锁屏小组件：Daytodo、最近待办、添加任务、任务进度。
- 小组件可查看今日待办、快速添加事件、启动番茄专注、查看进度。

产品含义：

- 小组件让 Todo清单从“需要打开的 App”变成“随手可见的任务环境”。
- 对执行型产品来说，减少打开应用前的阻力很关键。

### 8. 账户、安全与个性化

核心能力：

- 登录方式：微信、QQ、手机号验证码、邮箱密码、账号密码。
- 绑定与账户设置：头像、昵称、性别、手机号 / 微信 / QQ 绑定。
- 当前登录设备管理，可退出其他设备。
- 注销账户。
- 隐私政策入口。
- 隐私密码锁：手势密码或指纹解锁。
- 语言、应用图标、音效、振动、夜间免打扰、主题皮肤。
- 番茄专注模块和日程概览模块可开关。

产品含义：

- 它既服务轻量用户，也考虑长期使用者的数据安全和个人偏好。
- 模块开关是一种缓解功能膨胀的方式：功能可以丰富，但默认体验要可控。

## 关键用户路径

官方推荐的使用路径可以抽象为：

1. 创建分类清单，例如工作、生活、学习。
2. 思考今天和明天的待办事项，避免过多重复事件和提醒。
3. 为事件设置工作量，便于后续量化复盘。
4. 对暂无确定日期的事项放入待办箱。
5. 在列表里长按拖拽，按重要性排序。
6. 使用番茄专注开始执行。
7. 勾选完成。
8. 定期查看数据复盘。

这个路径的重点不是“把所有事情都放进系统”，而是“让系统辅助你今天真的完成一些事情”。

## 产品取舍分析

### 明确拒绝复杂方法论堆叠

Todo清单没有把所有流行时间管理方法都塞进产品。四象限、时间段排程、番茄暂停等能力被官方明确排除或暂不考虑。这能保护产品主线，但也会失去一部分偏好精细排程的用户。

### 用顺序代替优先级字段

很多任务工具用 P0 / P1 / P2 或颜色做优先级。Todo清单更倾向通过拖拽顺序表达重要性。好处是直观、少字段；风险是当任务很多时，用户可能需要搜索、筛选、文件夹、标签等能力补足。

### 提醒依赖系统日历

事件提醒通过系统日历协同实现，官方理由是触达率和无后台。好处是省电、可靠、少后台负担；代价是需要日历权限，且不同设备品牌体验可能不一致。

### 克制理念与功能丰富度之间存在张力

虽然官方强调化繁为简，但产品实际已经覆盖分类、重复、子任务、图片、语音、日历、番茄、报表、小组件、主题、隐私锁等大量能力。后续设计要特别注意默认路径，不然“功能丰富”可能反过来伤害“专注今天”的主张。

## 对晷迹的启发

### 1. 先定义一条不可动摇的主路径

晷迹的第一条主路径建议是：

捕获任务 → 排到今天 / 明天 / 无日期 → 拖拽排序 → 开始专注或执行 → 完成 → 查看复盘。

这条路径应优先于项目管理、复杂标签、四象限、甘特图、自动排程等高级功能。

### 2. 今日视图应成为产品第一屏

Todo清单的 Day Todo 逻辑值得借鉴。晷迹第一屏不应是空泛首页，也不应是所有任务的仓库，而应是“今天我要推进什么”。用户打开应用后，应直接知道下一件事是什么。

### 3. 任务字段要服务执行，不服务装饰

建议晷迹早期字段控制在：

- 标题
- 日期：今天、明天、无日期、选择日期
- 顺序
- 完成状态
- 子任务
- 工作量或能量等级
- 专注记录

标签、附件、复杂重复、自然语言、分享、小组件可以进入后续阶段，但不要抢 MVP 主路径。

### 4. 数据复盘要从一开始进入模型

即使 UI 暂时不做完整报表，数据模型也应保留复盘能力：

- 完成时间
- 原计划日期
- 延期次数
- 工作量
- 专注时长
- 中断次数
- 连续完成天数

这样以后做昨日小结、周报、趋势、拖延分析时不需要大规模迁移。

### 5. 不要复制功能清单，要复制产品判断

Todo清单最值得学的不是“小组件很多”或“番茄功能完整”，而是它围绕一个判断持续取舍：时间管理工具的目标是减少计划摩擦，让用户回到当下执行。

晷迹需要形成自己的判断，例如：

- 我们是否主张每日有限事项？
- 我们是否允许用户把一天排满？
- 我们如何处理过期任务，避免用户产生挫败感？
- 我们是否把复盘作为核心价值，而不是可有可无的统计页？

## 晷迹 MVP 建议

P0：

- 今日视图：显示今天任务、完成状态、拖拽排序。
- 快速添加：支持今天、明天、无日期。
- 任务完成：记录完成时间。
- 无日期待办箱：承接未排期事项。
- 简单子任务：拆解复杂事项。
- 基础复盘：今日完成数、未完成数、完成工作量。

P1：

- 番茄或专注计时：绑定具体任务。
- 周视图 / 月视图：只做查看和轻量排期。
- 重复任务：先支持简单每日 / 每周。
- 搜索。
- 工作量趋势和延期统计。

P2：

- 跨平台同步。
- 小组件 / 锁屏入口。
- 自然语言识别。
- 图片附件。
- 日程分享。
- 高级数据报表。

暂缓：

- 四象限。
- 复杂时间段排程。
- 甘特图。
- 过早的多主题皮肤系统。
- 过重的社交和公开便贴。

## 待进一步验证的问题

- Todo清单真实 App 的默认首屏、首日引导和空状态体验，需要实际安装后验证。
- 各平台版本号不一致，需要确认官网、App Store、应用宝、桌面端下载包的真实最新版本。
- 官方提到的用户调查数据缺少原始样本，不能直接作为晷迹需求依据。
- 高级账户具体权益在页面上没有完整展开，需要实测或查看客户端内购买页。
- “无后台”与番茄、提醒、小组件刷新之间的技术边界，需要移动端实测。
