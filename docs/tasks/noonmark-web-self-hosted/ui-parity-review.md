# Web 与原生界面的还原审查

**当前 Web 是可运行的功能预览，尚未达到原生界面的还原要求。** Day Todo 的三栏能力、日期 strip、行内新增、右侧复盘及列表信息密度均有明显差距。浅色背景、线性分隔和相近蓝色只覆盖了部分视觉基调，不能据此声称界面已经还原。

- Task-ID：`noonmark-web-self-hosted`
- 审查日期：2026-10-13。
- 范围：只读审查与下一轮实施约束；本轮不修改前端。
- 约束：保留服务端唯一事实源、个人自部署和已通过的真实操作路径；不恢复 Web 本地优先或离线命令回放。
- 验收状态：尚无用户确认过的 Web 像素基线，不计算“还原百分比”，不把本轮截图设为默认 visual regression reference。

## 一处必须先处理的原生截图过期

[飞光截图](../../assets/screenshots/readme/flylight.png)及[原位编辑截图](../../assets/screenshots/readme/flylight-inline-edit.png)仍显示“飞光详情”右栏中的重复正文、时间和逐项操作，以及 composer 的“展开／收起”操作。但当前[飞光产品规格](../../product/idea-capture-spec.md)要求：

- 页面 composer 从开始就是完整编辑面，高度基线 `112pt`，不再提供展开／收起。
- 飞光继续使用共享可收起右栏外壳与搜索，但右栏内容留白，不重复选中条目的正文、时间或操作。
- 记录按自然日分组，正文双击原位编辑。

这不是单凭文档作出的推断。[WorkspaceDetailRails.swift](../../../App/NoonmarkMacApp/WorkspaceDetailRails.swift) 的 `.flylight` 分支实际返回 `EmptyView()`；[IdeasPage.swift](../../../App/NoonmarkMacApp/IdeasPage.swift)实际按日期分组，并使用共享 composer。`2b2bd75d22ae3ff6d74fe8c5760201646a7eb293` 删除了旧的飞光详情内容，晚于当前该截图对应的修改。

下一轮应还原飞光的日期分组、正文优先和原位编辑；任务页面保留上下文详情栏，飞光不恢复已经删除的重复详情。截图里的旧文案及 Sticky Note 旧 slogan 也必须按当前产品规格校正。在新的真实 Mac 图生成前，这两处旧截图只作为历史布局证据，不能用于像素门禁。

## 下一轮可直接执行的像素级实施提示

以下尺寸是待实施的 Web 目标，来自原生当前度量及明确的浏览器适配；不是本轮已经完成的测量结果。

### A. 桌面外壳与 Day Todo

以 `1200×768 CSS px`、DPR 1、亮色冷灰为首个对照视口。再验 `1440×1000` 与 `960×720`。左栏宽 `220px`、紧凑态 `72px`；通用右栏 `280px`、默认收起，选中任务自动展开。1200 宽且两栏展开时，中间区域为 `700px`，左右各 `20px` 内边距；右栏内部 padding `14px`。左右栏开关为 `28×28px` 完整命中区，形状为同向双 chevron。栏位变化不得改变页面总宽或产生横向滚动。

页面上沿从可用内容起 `20px` 左右进入标题行。Day Todo 以本实例时区的完整中文日期作 `20px / 600` 主标题，星期和日期类别随后排列；一般页面标题采用 `21px`。移除重复的“NOONMARK”眉题及第二个 Day Todo 大标题。导航文字 `14.5px`，行高 `34px`，图标 `14px`，按当前原生语义色映射；主文本与选中底面保持中性。品牌识别留在登录或实例设置，不占用一整块工作区导航高度。

标题下放置等宽 14 天 strip：星期、日期、今天描边、任务点各自独立；选中背景由同一层平移。日期区域使用 roving tabindex 和方向键，明确显示选中与今天的区别。不得以未格式化的 `<input type="date">` 替代整个日期 strip；日期选择控件仍可用浏览器友好的可访问实现。

strip 后保留单条分隔线；接着是当前／未来日的行内新增输入，与真实“从任务池排期”入口同排。普通行的状态控件保留 `28px` 命中区，标题为 `13px / 500`，行上下各 `8px` padding；元信息按实际存在情况展开，不能给无元信息行固定增加第二层高度。待完成与完成通过共享样式区分，不在右侧反复写 glyph 已表达的状态。完成操作必须仍由服务端确认，未知结果不可先进入统计。

右栏展开且未选任务时，顶部为每日复盘上下文；显示真实完成率、状态数量和近 7 天统计，再呈现已有三项复盘字段。统计从已有服务端事实派生，不放示例数字或假 AI 分析。选中任务后切换为同一个 rail 的任务详情；关闭选择恢复复盘，表单草稿与所选日期绑定。

### B. 飞光与 Sticky Note

沿用同一外壳。飞光 composer 默认完整展开：最小高度 `112px`、最大编辑高度基线 `220px`、圆角 `12px`、动作区高 `42px`、正文水平 inset `16px`、顶部 inset `13px`；主动作高 `32px`，正文 Enter 换行，平台 Command／Control＋Enter 保存。只为已实现的动作绘制工具入口，尚无分类能力时不画可点击的 `#`／`@` 假控件，也不恢复旧截图里的“展开／收起”。

时间线可读宽度上限 `760px`，按实例 IANA 时区的自然日分段；段间距 `18px`，日期标题下方 `4px`。条目正文在前，时间与真实分类／精选标记在后；条目水平 padding `12px`、垂直 `10px`、元信息间距 `6px`，相邻条目只用一条分隔线。正文采用共享 Markdown renderer；在安全渲染能力完成前保留纯文本并明确实施状态，不写“支持 Markdown”的虚假提示。

双击正文在原条目位置打开共享编辑器，取消、保存、错误与草稿恢复保持在同一上下文。共享右栏只保留布局外壳和搜索，不重复正文和逐项操作。Sticky Note 使用当前产品名及 slogan，只提供一个展示模式下拉菜单；清单流与自适应便签墙复用同一个条目内容组件，编辑跳回来源记录。两种呈现不增加领域副本，也不改变精选顺序。

### C. 移动适配

`390×844` 没有对应 Mac 像素基线，只验行为和信息层级。保留至少 `44px` 触控目标，导航变为可访问抽屉；详情／复盘可变为可关闭 sheet，不能把三栏硬挤到一屏。缩窄日期 strip 的可见窗口时必须保留当前日期、前后移动及可访问完整日期。抽屉关闭后不占 viewport，也不得留在键盘 Tab 顺序里；打开后焦点进入，关闭后返回触发按钮。输入聚焦、IME、长页面滚动、软键盘及未知提交结果提示均须复验。

## 验收与交付顺序

1. **先固定对照情境。** 使用 `make web-demo` 的真实一年 fixture，补齐桌面 Day Todo、任务详情、任务池、未来、完成／未完成、飞光原位编辑、Sticky Note 两布局和设置截图。记录视口、DPR、locale、时区、日期、所选条目、栏位及分组状态；只归档本轮合成资料。原生缺少当前可信图的页面，后续在 Mac 非生产 demo profile 重拍，不能启动 production 补图。
2. **先改外壳与 Day Todo。** 三栏、日期 strip、行内新增和右侧复盘为第一个独立验收片段。现有 JSON 命令、精确 revision、草稿隔离、IME、未知结果核对、认证和备份不得因 UI 重构降级。默认右栏收起和演示截图展开两种状态都要覆盖。
3. **再改已有事实的列表表达。** 日期分组、父子折叠、进度、轨迹摘要、任务池占位形状和语义导航计数，按同一 fixture 与原生逐项核对。数据尚不支持的分类／重复规则留在能力清单，不用静态 badge 假装已实现。
4. **随后改飞光与 Sticky Note。** 先日分组及共享原位编辑，再 Markdown／回看和两种展示模式。每个阶段均验证同一条目编辑、精选、移出、删除后的跨页面一致性。
5. **最后建立视觉门禁。** 先由用户确认新的真实 Web 图，再将明确批准的图作为 reference。几何门禁可立即验证 `220/72/280/20/14px`、完整命中区、无横向溢出及唯一 DOM id；字体栅格和平台控件差异单独列出，不设置一个大阈值把结构错误吞掉。

每次验收都保留桌面顶端与长列表底端、移动顶端与底端、栏位开合及键盘焦点证据。截图必须等待对应状态成立，如侧栏实际退出 viewport、记录加载完成；不靠固定 sleep。布局对账报告要逐项写明“符合／差异／未取证”，把缺领域能力与视觉差异分开。完成真实操作测试只能证明功能路径，本项还原审查必须有独立结果。
