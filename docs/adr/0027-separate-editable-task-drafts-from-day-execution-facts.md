# ADR 0027：分离可编辑任务草稿与日执行事实

- 状态：已接受
- 日期：2026-07-22

## 背景

任务池的计划子任务保存在 `TaskDefinition`，Day Todo 的实际子任务保存在 `DayTrace`／`Subtask`。旧实现把两者当成互不回流的单向快照：回池只改变日轨迹状态，重新排期又从旧任务定义生成内容。因此，在 Day Todo 新增的描述、附言和子任务会在回池后消失；已有历史的任务池条目也被错误锁成不可编辑。

变更与延续分别手工搬运不同字段，进一步造成描述、附言、子任务和来源关系不一致。延续还允许从较早历史再次发起，可能形成分叉执行线。

## 决策

1. `TaskDefinition` 的当前版本表达任务池中“下一次执行”的可编辑草稿；`DayTrace` 表达某一自然日已经形成的执行事实。
2. 回池不覆盖历史定义。系统从来源日轨迹生成下一版任务定义，带回最新描述与未完成子任务，并把最新附言复制回同一任务链。已完成子任务只留在来源历史。
3. 任务池草稿可以编辑标题、描述、附言和计划子任务。待完成且未锁定的当前／未来日轨迹可以编辑描述和子任务；子任务删除保留内部 `cancelledDraft` 事实并退出用户投影。
4. 变更表示形成新承诺，因此创建新任务链；新任务默认继承来源日轨迹的描述、附言和未完成子任务，旧、新任务通过显式变更关系双向呈现。已完成子任务不进入新承诺。
5. 延续保持同一任务链，只能从当前最晚执行前沿发起，目标日期必须晚于来源日期。它仅复制未完成子任务并保留子任务轨迹线；完成项留在历史日期。
6. Todo diff 的过期摘要只包含会改变 Todo 操作合法性或语义的任务事实。分类状态与 Todo 状态正交，不参与该摘要；任务内容和日期等实质变化仍使草稿过期。

## 后果

- 回池、再排期、变更与延续不再丢失当前可执行内容。
- 历史事实保持 insert-only／版本化语义，用户删除子任务不会物理擦除同步身份。
- 任务变更继续具有新任务链身份，同时用户可以从新任务明确返回来源任务。
- 后台自动分类不会再无故撤销用户已经审查的 Todo diff。
- Core、SQLite、同步与真实 App E2E 必须共同验证内容继承、唯一执行前沿和写入回执。
