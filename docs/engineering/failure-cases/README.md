# 晷迹故障案例库

本目录保存已经真实发生的工程故障及其证据闭环。目的不是淡化责任，也不是罗列代码变更，而是让后续开发者能够回答：谁在什么变更中引入了什么故障、为什么既有门禁没有拦住、根因如何修复，以及以后用什么自动化约束防止复发。

## 命名与状态

- 文件名：`YYYY-MM-DD-<简短英文故障名>.md`。
- 案例 ID：`FAIL-YYYY-MM-DD-NN`，同一天从 `01` 递增。
- 状态只使用「处理中」或「已修复」。
- 一个根因对应一个案例；同一根因的后续补充更新原案例，不另建重复案例。

## 必填模板

```markdown
# FAIL-YYYY-MM-DD-NN：故障标题

- 状态：处理中／已修复
- 首次发现：ISO 8601 时间或已知最小时间范围
- 影响版本／构建：版本、build、source commit
- 引入提交：完整 commit SHA 与标题
- Git author／committer：Git 记录值
- 实际修改者：证据可确认的人员／agent；无法确认时写「未知」
- 修复提交：完整 commit SHA；提交前保持「待回填」

## 用户症状与影响

## 时间线

## 复现与证据

## 排除的假设

## 根因与破坏机制

## 根因修复

## 验证结果

## 发行与回滚

## 教训与永久约束
```

## 归档规则

证据必须来自源码或运行产物。个人归因必须区分 Git identity 与实际操作者；仓库无法证明实际操作者时必须写「未知」。案例不得包含用户业务内容、正式资料路径、账号、凭证、同步 payload 或其他隐私资料。修复 commit 正文必须引用案例 ID，原始症状级验证未转绿前不得将状态改为「已修复」。
