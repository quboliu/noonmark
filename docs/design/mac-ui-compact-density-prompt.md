# Mac UI 紧凑密度像素级实现 Prompt

## 参照与目标

以用户于 2026-07-13 提供的 TickTick / 滴答清单并排截图为视觉参照，并以同一台机器的真实窗口边界作为尺寸证据：TickTick 当前窗口为 `1000 × 768pt`，晷迹早期窗口为 `1320 × 820pt`。窗口 chrome 已统一改由 AppKit 原生组件绘制，不再人工匹配 traffic light 尺寸。

本文件描述当前唯一的紧凑界面，不保留早期行内动作或有框描述编辑器。结果应像同一个产品整体缩小一档，并把低频动作收进任务右键与详情三点菜单；不能只缩字体而保留重复入口、松散留白或多余容器。

## 唯一当前尺寸

- 主窗口默认启动尺寸必须是 `1200 × 768pt`；右栏展开后中栏约 `700pt`，右栏收起后中栏约 `980pt`。
- 主窗口最小尺寸必须是 `960 × 720pt`。
- 左侧 Sidebar 完整宽度必须是 `220pt`，紧凑图标列必须是 `72pt`；仍只显示一列图标，并确保分隔线不压住原生绿色 traffic light。
- 通用右侧 Detail Rail 宽度必须是 `280pt`。
- 通用 Detail Rail 默认收起；点击任务时自动展开，也可由面板边界的双 chevron 手动切换。切换时窗口 frame 保持不变，中栏精确让出或收回 `280pt`。
- 日历内部分析 rail 宽度必须是 `248pt`。
- 页面主要水平 padding 从 `24pt` 收紧为 `20pt`；列表行主要纵向 padding 从 `9–10pt` 收紧为 `7–8pt`。
- 不设置虚假的最大内容尺寸；窗口继续支持系统缩放、关闭后保留进程及 Dock 重新打开。

## 原生窗口标题栏与导航

- titlebar 使用 `NSWindow` 原生 full-size content，不安装空 `NSToolbar`；三栏表面延伸到窗口顶端，traffic lights、窗口圆角、边界和阴影仍由系统绘制，不保留 SwiftUI 自绘副本或横贯全窗的空白占位。
- titlebar 不显示 Clock Logo、品牌字、重复标题或左右栏开关。栏位按钮进入对应面板的内侧边界，使用两个同向 chevron、完整可点击的 `28 × 28pt` 矩形和轻量 hover；无详情内容时不得显示右侧入口。
- 左栏完整宽度为 `220pt`，紧凑态为 `72pt`：保留居中的导航图标和当前页轻量选中底，隐藏名称、数量与分组标题。完整态以 `<<` 收起，紧凑态以 `>>` 恢复；右栏展开态以 `>>` 收起，隐藏态在页面标题行右端以 `<<` 恢复。
- Sidebar 内容在其独立 Hosting pane 内保留原生顶部 safe area，再加 `4pt` 内容 padding；中栏与右栏则在各自 Hosting 边界进入 full-size content titlebar，不能叠加第二层标题栏留白。
- 导航 icon 视觉字号从 `15.5pt` 缩为 `14pt`，占位宽度从 `21pt` 缩为 `19pt`。
- 导航主文字使用最终可读尺寸 `14.5pt`，导航行高从 `36pt` 收紧为 `34pt`。

## 字体与图标密度

- 所有 SwiftUI 显式系统字体、继承字体、SF Symbols、AppKit `NSFont` 编辑态和原生附言操作控件必须使用同一个紧凑尺度源。
- 全局字体 scale 固定为 `1.0`；调用点传入的尺寸就是最终渲染尺寸，只允许统一四舍五入到最近的 `0.5pt`，不得再次整体缩小可读文字。
- `21`、`17`、`15.5`、`14.5`、`14`、`13`、`12.5`、`12`、`11` 与 `10.5pt` 均保持各自 token 尺寸；低于 `10.5pt` 的微型字同样不得经全局 scale 继续缩小。
- Songti SC 诗文、Markdown 编辑态与 Markdown 展示态必须使用同一个 `1.0` 尺度源，不能在进入编辑时改变字号。
- 禁止使用根视图 `scaleEffect`、渲染后缩放或模糊变换；布局尺寸、字体和图标必须由 token 驱动。

## 快速新增输入

- Day Todo 与任务池的快速新增继续共用同一个 `32pt` 单行编辑器，不新增标题、提示块、按钮、焦点描边或第二层容器等视觉单位。
- 页面内快速新增与独立“快速记录”统一使用 `#标签`、`@分组`；输入符号后只展示对应 active 目录候选，候选消失时不保留空容器。独立弹窗按候选数量向下增高并在候选关闭后恢复，主输入框位置不得跳动。
- 每个任务最多一个 `@分组`；检测到多个分组时在输入框下方显示单行错误并阻止提交。含空格的候选自动补全为带双引号形式，避免候选名称被拆入任务标题。
- compact 字体使用 `12.5pt`。文字、placeholder 与原生 AppKit 插入点必须共享同一垂直基线；真实 `NSTextView` 聚焦后，插入点中心与输入框中心误差不得超过 `0.5pt`，上下留白差不得超过 `1pt`。
- 无修饰键 Return 必须经真实窗口 responder path 提交当前内容；存在 IME marked text 时，首个 Return 只交还 AppKit 确认组合态，不得提前创建任务，下一次无组合态 Return 才提交。成功后实际 `NSTextView`、SwiftUI binding 与输入 placeholder 状态必须同步清空。Day Todo 生成当天 pending trace，任务池生成未排期 active chain。
- Day Todo 与任务池必须使用全局唯一的真实 App UI 锚点。验收必须鼠标聚焦屏幕上的输入框，再由其所属 `NSWindow` 发送普通文本和 Return；脱离窗口新建 `NSTextView`、直接写 Store 或直接调用新增方法都不算交互验收。
- Day Todo 日期 strip 必须在真实鼠标点击日期后进入原生 first-responder 链；方向键验收必须由所属 `NSWindow` 发送左右 `NSEvent`，不得直接调用日期移动方法。

## 关键页面密度

- Day Todo 页面标题使用 `21pt`；14 日 Date Strip 在 `500pt` 主内容宽度内完整展示，不得横向滚动或丢失日期。
- 任务行标题约 `13pt`，正文约 `12pt`，元数据约 `10–11pt`；状态与操作的透明点击区不得随 glyph 缩小。
- 默认 `1200×768pt` 窗口下，任务池带详情栏时主内容约 `700pt` 宽。任务池行只允许一个内容轴：`18pt` 未排期 glyph、完整可读标题和分类摘要同排；行内不得出现排期按钮、删除按钮或动作专用次级行。行高由内容和 `7–8pt` 上下 padding 决定。
- 任务池任务右键与详情右上角三点菜单必须复用同一动作内容，顺序固定为“排期到今天 / 排期到明天 / 选择日期… / 分隔线 / 删除任务”。右键触发区域是整条任务行，不新增尾箭头、常驻省略号或 hover 工具条。
- 未来计划继续只在行内保留状态和优先级直接调节；改期与回池留在右键。未完成列表把“延续到… / 废弃任务链 / 重新启用”移入右键，保留轨迹跳转和明细展开。已完成任务与已完成子任务把“查看当天 / 复制为新任务”移入右键。完成圆点、子任务展开和优先级调节属于高频直接操控，不迁入菜单。
- 详情三点菜单已有的动作不得在详情正文再次组成“排期”“计划操作”或底部按钮区。菜单隐藏不计常驻视觉单位，但必须保留完整能力。
- 任何任务列表按分组显示线性分组标题时，普通任务行不得再次用分组 badge 重复同一信息；平铺视图的任务行正常显示分组。Day Todo 置顶队列以图钉分组头标识（只显示图钉图标与计数，不写文字），置顶任务行内不再显示图钉图标；已分组的置顶任务仍显示一个分组 badge；未分组置顶任务不补造 badge。所有任务行最多显示两个标签。
- 分组与标签 badge 必须保持自身文字的 intrinsic width，禁止压成只剩图标或空色块。横向空间不足时依次显示 `2 → 1 → 0` 个标签，并把所有未展示标签合并为可点击的 `+N`；popover 必须仍列出全部标签，不能丢数据、换成不可操作省略号或增加一排装饰容器。
- Detail Rail 内边距为 `14pt`，普通区块间距为 `12pt`。详情页眉与任务主文本是两个层级；任务标题和描述必须再组成一个内部 `6pt` 间距的主文本组，不能让普通区块的 `12–14pt` 间距叠加标题编辑器空高。
- 任务池计划子任务与 Day Todo 子任务共用多行编辑语义：标题按详情栏实际可用宽度自然换行，子任务行必须承接完整编辑器高度，左侧状态与右侧动作按首行对齐；相邻子任务及底部新增输入框的可见 frame 不得相交。极长标题达到 `120pt` 高度上限后才允许在本行内部滚动。
- 单行任务标题编辑器的可见高度为 `22pt`；多行内容按实际文本增长，最高 `72pt` 后内部滚动。描述正文为 `11pt`，空白或单行时可见高度至少 `32pt`，按内容增长到 `132pt` 后内部滚动。标题与描述的文本 inset 均为 `3pt`，字形底部到描述首行字形顶部目标为 `10–14pt`，不得超过 `16pt`。
- 描述编辑器闲置态和焦点态都不绘制描边、圆角底色或第二层卡片；只保留文本、placeholder、选区、插入点和滚动能力。只读描述同样不加容器。焦点不得通过新增视觉单位表达。
- “分组”行只有一个当前值入口：当前分组 chip（或“无分组”占位）本身就是 Menu label，并在尾部保留一个 `7pt` chevron；不得再显示“选择 / 更换”按钮。管理是不同能力，保留为同排独立入口。
- 描述使用原生 `NSTextView` responder chain。编辑菜单必须提供撤销、重做、剪切、复制、粘贴、删除、全选；`⌘A` 与用户要求的 `Control-A` 都能全选，`⌘Z / ⇧⌘Z` 优先作用于当前文本编辑器。Markdown 保留 `⌘B` 粗体、`⌘I` 斜体、`⌘E` 行内代码、`⌘K` 链接、`Shift-Return` 硬换行和普通多行输入；无修饰 `Tab`／`Shift-Tab` 移动键盘焦点，`Option-Tab` 才插入四个空格，不新增常驻格式工具条。
- 烛龙 composer 高度从 `58pt` 收紧至 `54pt`，固定 workflow 行高从 `68pt` 收紧至 `62pt`，继续保持单一视觉轴与扁平列表。
- 烛龙空首页的 PageHeader、composer 与固定 workflow 作为一个稀疏内容组，在主页可用视口内垂直居中并共用左对齐轴；存在待处理会话时才整体顶对齐并自然滚动。Composer 使用 `14pt` 普通圆角矩形，不得保留胶囊外形。
- 分类管理浮窗、设置页、日历、未来计划、未完成池、已完成池在新窗口宽度下不得裁切操作、隐藏信息或出现水平溢出。

## 禁止项

- 不得保留 `1000 × 768`、`1080 × 768`、`1320 × 820`、`1180 × 760` 或任何旧 `defaultLaunch*` 兼容别名与双路径。
- 不得通过删减 Detail Rail、隐藏按钮、截断英文文案或减少 14 日 Date Strip 来换取适配。
- 不得逐页散落新的缩放常数；窗口、壳层、字体和 icon 尺度必须来自 `NoonmarkMacUIContract` 的唯一当前 token。
- 不得把归档 HTML 原型作为视觉 oracle，也不得自行生成 golden reference。
- 不得为已经迁入右键或三点菜单的动作保留隐藏兼容按钮、旧枚举、旧几何锚点或反向要求其出现的测试数据。

## 真实 App 验收

- CGWindow 必须报告唯一主窗口 `1200 × 768pt`，对应 Retina 截图 `2400 × 1536px`。
- 真实 `.app` E2E 必须覆盖 Day Todo、任务池、未来计划、未完成、已完成、日历、烛龙、设置、任务详情、分类管理浮窗和 English 文案。
- 截图必须逐页检查文字截断、控件碰撞、横向溢出和视觉密度；运行日志不得出现 fatal、assertion 或 persistence failure。
- 任务池真实 UI 几何探针必须在 `1200×768pt` 与 `960×720pt` 下确认每个可见任务标题和分类 badge 都达到其文字所需宽度，且三项排期及删除均不在行内 view tree；真实右键必须出现完整菜单并能从同一共享入口完成排期。
- 详情真实 UI 几何探针必须测量标题字形、描述首行和编辑器外框：字形间距 `10–14pt`、无可见描述 surface、当前分组值就是菜单入口，且详情正文没有重复动作区。
- Markdown 真实窗口 E2E 必须让描述 `NSTextView` 成为 first responder，通过 App 主菜单和窗口事件发送 `⌘A / ⌘C / ⌘X / ⌘V / ⌘Z / ⇧⌘Z`，核对选区、字符串、pasteboard、binding 与持久化；脱离窗口直接 new `NSTextView` 的 probe 不算验收。
- resize probe 必须验证 `960 × 720pt` 最小尺寸仍可用，并能从最小尺寸恢复默认尺寸。
