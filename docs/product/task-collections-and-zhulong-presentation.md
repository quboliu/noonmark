# 任务集合与烛龙呈现升级规格

- 状态：实施基线
- 日期：2026-07-20
- 任务级别：P
- 影响范围：`NoonmarkCore`、`NoonmarkMacRuntime`、`NoonmarkMacApp`、`NoonmarkStorage`、`NoonmarkSync`、真实 App E2E

## 目标

本轮同时解决五项用户路径：任务标签从所有未选目录项中选择；分组根据用户认可状态决定是否使用彩色身份；任务池、未完成与已完成支持统一的排序及分组方式；烛龙页面与自动分类／标签分别开关；进入烛龙会话后默认成为干净的单列对话，并保留三种旧会话投影。烛龙首页维持既有布局与信息架构，不纳入此重构。

## 领域与呈现边界

### 分组认可

分组目录项增加明确的呈现认可状态：

- `userApproved`：用户直接创建，或在管理页明确认可／修改过；允许使用目录颜色呈现文字与图标。
- `pendingAIReview`：由自动 AI 首次创建且尚未被用户处理；文字与图标使用普通主文字色。

认可状态属于目录项事实，不从颜色、名称或当前任务关系来源推测。AI 把任务放进既有人工分组，不会降低该分组的认可状态。用户重命名待认可分组时原子地把它提升为已认可；管理页另提供显式认可动作。同步、快照、SQLite 和导入导出沿用目录项 Codable 事实；项目尚未发布，按 clean cut 只支持当前 schema。

分组图标首版继续使用统一的 `folder.fill`。本轮“图标和颜色”指分组标题及详情分类标识同时显示该图标，并让图标与文字共同遵循认可后的目录颜色；不引入尚未被需求定义的任意图标编辑器。

### 任务集合呈现

三个页面共享同一呈现模型：

- 组织：`flat`／`grouped`。
- 排序键：`time`／`title`。
- 方向：`ascending`／`descending`。

这三个正交字段形成用户要求的八种组合。分组标题始终按本地化名称稳定升序排列，“无分组”固定置后；方向只作用于组内任务，避免同一分组在切换方向时上下跳动。

时间语义按页面真实事件定义：

- 任务池：当前任务定义的创建时间。
- 未完成：最近一次活跃／未完成轨迹时间，缺失时回退到定义创建时间。
- 已完成：任务或子任务的完成时间。

字母排序使用本地化标准比较，稳定 tie-breaker 使用领域 ID。已完成子任务以自己的标题排序，并继承父任务在完成轨迹时的分组投影。

这些是本机呈现偏好，不进入领域同步记录。使用专用 UserDefaults repository 持久化，每个页面分别保存；解码失败时 fail-closed 回到默认值。当前默认保持现有页面习惯：任务池按分组＋时间升序，未完成按时间降序，已完成按时间降序。

### 标签选择

任务详情的标签添加入口改为原生菜单／弹出列表，完整列出活动目录中当前未选的标签。选中后立即保存并从列表移除；删除后重新出现。列表保留“创建新标签”入口，只有用户选择创建时才出现文字输入框。目录为空或所有标签均已选时显示明确状态，不生成重复标签。

### 能力开关

Provider 配置、烛龙页面和自动分类／标签是三个边界：

- Provider `enabled`：该 Provider 是否可执行远程调用。
- Zhulong page `enabled`：导航和烛龙会话入口是否可见。
- Automatic classification `enabled`：新任务是否入队并由 Provider 自动生成分组／标签。

后二者使用独立本机功能偏好。关闭自动分类会停止 worker 并不再为新任务入队，但保留已有目录、关系、作业审计与手工重试事实；重新开启后只处理开启后的新任务，除非用户通过既有 backlog 决策明确处理旧任务。关闭烛龙页面只改变入口与当前页面回退，不清除会话或 Provider 凭证。

### 烛龙四种投影

一份 append-only 会话记录投影到四个独立 renderer：

1. `conversation`：全新默认。单列对话、底部常驻 composer、烛龙正文无外围卡片、用户消息轻量底色、工具／计划／状态默认摘要并可展开。
2. `dossier`：连续卷宗，恢复旧 A。
3. `chapters`：章节手风琴，恢复旧 B。
4. `weave`：双轨编织流，恢复旧 C。

`conversation` 不复用后三者的视觉容器，只共享语义记录、动作闭包与右侧检视路由。切换只改变本机投影偏好，不能改变日志、canonical head、checkpoint、授权、运行 producer、未提交输入或专业产物。首次及 clean cut 后默认 `conversation`。

视图切换入口放在 PageHeader，并在 composer 附近提供紧凑的当前视图入口。右侧详情仅按需承载 Todo diff、计划草稿、证据、范围与事件历史；每个结果在对话流中保留摘要和重新打开入口。

## 实施顺序

1. 先为分组认可、任务集合偏好、独立功能开关和四视图偏好补测试。
2. 修改领域模型及存储／同步闭环，再接管理页和分类展示。
3. 接入三个任务集合页的共享控制器与页面投影。
4. 拆分设置开关和自动分类 worker 门禁。
5. 新建默认对话 renderer，恢复三个旧 renderer 与切换入口。
6. 扩展真实 App E2E fixture、可访问性锚点、持久化探针和截图场景。

## 风险与控制

- **目录状态漂移**：认可状态随目录项持久化，并在自动创建、用户创建、认可、重命名和同步合并测试中对账。
- **自动分类停机竞态**：worker 每次领取与提交前重新检查开关；关闭后取消调度，已取得但未提交的运行不得越过最终门禁。
- **历史分类分组错误**：完成页以轨迹快照投影分类，不用当前关系覆盖历史；缺失目录认可信息时保守使用普通主文字色。
- **四视图状态丢失**：renderer 不持有领域状态；草稿与选择提升到 workspace 层，切换测试逐项对账。
- **视觉单位回潮**：默认对话只允许消息身份、正文、单行状态与 composer；专业容器按需出现，不把旧 renderer 组件引入默认路径。

## 回滚、灰度与监控

项目尚未发布，没有生产灰度面。交付以单分支原子 commit 为回滚单位；若真实 App 验证失败，保留旧 commit 的可构建产物并使用 `git revert` 回退整个功能提交，不做兼容分支或旧 schema 迁移。

运行监控使用现有结构化 App 日志、自动分类作业／circuit 状态、E2E App 日志与 SQLite 探针。新开关变化、worker 停止／恢复、分组认可提交和烛龙视图恢复失败必须留下可定位日志，但不得记录 Provider 凭证或用户完整对话正文。

## 验收

- 标签菜单对已选集合做精确补集，并能创建新标签。
- 人工与已认可分组在任务池标题、行内分类和右侧详情使用彩色文字与图标；待认可 AI 分组使用普通主文字色。
- 管理页认可和重命名都能持久提升认可状态，重启保持。
- 三个任务集合页的八种组合均有确定性排序；切换和重启保持偏好。
- 烛龙页面、自动分类／标签和 Provider 三者可独立启停。
- 新安装默认普通对话；卷宗、章节、双轨均可切换，切换前后日志、授权、草稿与运行状态不变。
- 真实 `.app` 在正常与最小窗口完成四视图截图、长流滚动、右侧检视、设置、标签和三任务页交互。
- `make check`、真实 App E2E、持久化探针和 DMG 构建／安装启动全部通过。
