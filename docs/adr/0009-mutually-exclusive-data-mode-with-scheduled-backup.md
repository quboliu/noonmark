# 主数据模式互斥，并允许旁路定时备份

**Status**: Accepted

晷迹需要同时支持本地优先和在线优先两种产品形态，但它们不能并行作为主数据运行路径。用户可以在初始化时选择，也可以后续切换；任何时刻只能有一种主数据模式写入任务事实。

**Context**

本地优先能保证离线可用、响应快和数据可控，但会带来多设备离线分区后的冲突合并复杂度。在线优先能把主写入顺序收敛到在线服务，冲突处理更接近单一事实源，但会依赖服务可用性、账号和网络。

如果把两种模式同时打开，会出现两个危险结果：

- 两套同步链路同时写入同一份任务事实，产生不可解释的覆盖和冲突。
- 用户无法判断当前事实源到底是本机、iCloud、S3 备份，还是在线服务。

同时，在线优先用户仍然需要可恢复备份。定时备份应该允许存在，但它不能被设计成第二套双向同步。

**Decision**

- `AppPreferences` 增加 `dataMode`：
  - `localFirst`
  - `onlineFirst`
- `dataMode` 是唯一主数据模式开关；同一时刻只能有一个值。
- `AppPreferences` 增加 `backupPolicy`：
  - `frequency`: `off | daily | weekly`
  - `destination`: `iCloudDrive | s3`
- 定时备份只导出可恢复数据包，不接收远端变更，不参与冲突合并。
- 在线优先可以启用定时备份；这不代表本地优先同步仍在运行。
- 设置页必须用文案说明“主数据模式互斥；定时备份是旁路导出”。
- SQLite 通过 `sync_settings` 保存数据模式和备份策略，避免对既有 `app_preferences` 表做脆弱列迁移。

**Consequences**

- 初始化向导和设置页可以复用同一套偏好字段。
- 后续 `SQLiteSyncCoordinator` 或在线服务 coordinator 必须先读取 `dataMode`，只启动对应主链路。
- 备份 adapter 可以独立支持 iCloud Drive、S3 或其他对象存储，但不得调用双向 merge。

**Alternatives Considered**

把在线优先和本地优先都作为可同时开启的同步能力：短期看起来灵活，但会产生双事实源和双冲突解决器，风险不可接受。

把定时备份当作同步端点：这会让用户误以为 iCloud Drive/S3 也参与双向同步。备份必须被限制为可恢复导出。

只保留本地优先，不提供在线优先：实现更简单，但不能覆盖需要集中在线数据服务的用户和未来商业化路径。
