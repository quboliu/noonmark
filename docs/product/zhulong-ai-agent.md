# 烛龙 Agent 产品规格

本文定义晷迹的 **烛龙**。烛龙是普通清单能力之外的可选辅助 Agent，通过有界会话承载任务成形、每日收尾、重新排期和分类整理。它不能成为 Day Todo、任务池、未完成池、已完成池或每日复盘的运行依赖。

## 设计原则

- 普通清单功能在没有网络、没有账号、没有 AI provider、AI provider 故障时必须完整可用。
- 普通 Provider 产物只能进入当前烛龙会话，不能直接改写 Todo 或历史日轨迹；ADR 0026 的新任务自动归类是唯一例外，并只能写该任务的当前分组／标签。
- 烛龙对当前日或未来计划的任何创建、排期、变更、延续、废弃或分类修改，都必须先形成绑定当前会话、证据版本和来源的 Todo 变更 diff，再由用户明确确认后调用普通领域接口。
- 烛龙不依赖任何一本时间管理书或单一理论。它可以引用理论作为分析视角，但最终判断必须回到用户自己的任务轨迹证据。
- 烛龙的人格是独立、冷静、直指事实的复盘伙伴：它不讨好用户，不用道德化语言惩罚用户，也不把一次失败永久贴成人格标签。

## 命名与意象

烛龙的命名来自《苦昼短》中的“衔烛龙”意象：时间在日月寒暖中煎熬人寿，晷迹要做的不是美化时间，而是把用户真实留下的轨迹照亮。

《苦昼短》可作为烛龙页面、空状态、关于页或复盘入口的完整 slogan 元素。设计时不应把全诗做成压迫式大段正文，而应作为可展开、可滚动或仪式化的视觉元素。

> 飞光，飞光，劝尔一杯酒。
> 吾不识青天高、黄地厚，
> 唯见月寒日暖，来煎人寿。
> 食熊则肥，食蛙则瘦。
> 神君何在？太一安有？
> 天东有若木，下置衔烛龙。
> 吾将斩龙足、嚼龙肉，
> 使之朝不得回、夜不得伏。
> 自然老者不死、少者不哭。
> 何为服黄金、吞白玉？
> 谁似任公子，云中骑碧驴？
> 刘彻茂陵多滞骨，嬴政梓棺费鲍鱼。

诗文本采用维基文库《苦昼短》通行文本：https://zh.wikisource.org/zh-hans/苦昼短 。后续如果要做古籍校勘版本，可另建文案资产，不影响产品规则。

## Provider 模型

烛龙必须支持自定义 provider。

核心字段：

- `providerId`
- `displayName`
- `kind`：OpenAI-compatible、本地模型、自定义 HTTP
- `baseURL`
- `model`
- `apiKeyRef`
- `extraHeaders`
- `enabled`
- `createdAt`
- `updatedAt`

规则：

- API Key 只能进入系统 Keychain 或等价安全存储，不能进入普通配置文件、日志、导出数据包或崩溃报告。
- 每个 Provider execution revision 使用独立、不可变的 Keychain 凭证引用；新凭证先落 Keychain，再切换非敏感配置指针。旧 revision 只在下一次 fresh launch 确认持久指针后回收；显式清除先删固定 service 内的凭证，再删非敏感指针。请求只能解析与其 revision 完全一致的引用，崩溃恢复不得把新 Key 发往旧 URL 或旧模型。
- 远程 Provider 只允许 HTTPS；明文 HTTP 仅开放给 `localhost`、`127.0.0.1` 与 `::1` loopback。
- 开发者显式运行 DeepSeek live smoke 时，可由本机专用、Git 忽略且权限固定为 `0600` 的 `config/ai-provider.local.json` 经 shell 环境注入测试进程；正式 App 不读取或同步该文件，保存到烛龙设置的凭证仍只进入对应 App 身份的 Keychain。
- provider 未配置或不可用时，烛龙入口显示为可配置状态，普通清单功能不降级。
- provider 配置允许测试连接，但测试连接失败不能阻止用户继续使用清单。
- 第一版不做内置云端账号绑定。未来可以增加原生云 AI provider，但不能移除自定义 provider。

## 数据访问边界

烛龙默认只读取用户主动选择的范围。

可选范围：

- 当前 Day Todo
- 某个历史日
- 最近 7 天、30 天或自定义日期范围
- 未完成池
- 已完成池
- 任务池
- 用户选中的任务链
- 主分类与标签目录及任务分类统计

规则：

- 每次向远程 provider 发送数据前，界面必须让用户知道将使用哪些范围的数据。
- 不能发送数据库文件、内部 ID、Keychain 值或同步端点配置。
- 对外发送的任务数据应尽量使用最小必要字段：标题、日期、状态、子任务、延续次数、复盘文本、主分类、标签，以及用户授权范围内仍有效的附言正文。
- 不向 Provider 发送附言内部 ID、时间戳或删除墓碑；已删除附言正文不能进入提示词。
- Provider 创建任务时最多提供一个 `initialNoteBody`。条目身份和时间必须在用户确认后由 NoonmarkCore 生成；Provider 不能提供既有附言的身份，也不能直接编辑或删除既有附言。
- 烛龙生成的分析结论必须带可追溯证据，例如“过去 14 天 6 个大任务中有 5 个发生延续复制”。

## 会话、授权与应用边界

- 每次工作从一个有界烛龙会话开始；主要意图、数据范围、Provider 配置身份和上下文版本都属于该会话。
- 设置分别为任务数据读取与远程发送提供允许、询问和禁止三态权限上限；禁止在建立会话或 Provider 请求前 fail-closed，询问只在新会话开始时确认一次。
- 会话数据授权不按时间过期。数据范围扩大、远程 endpoint 改变或本地／远程性质变化时必须重新确认；显示名称、模型和能力声明变化不单独触发确认。
- 会话与上下文 rail 持续披露当前数据范围和实际接收方，用户可以暂停或删除会话；不能继承一份跨会话万能授权。
- 任务成形先形成用户可审查的规划简报；一次性规划委托只允许 Provider 产出结构化规划，不包含 Todo 写入权限。
- 结构化规划必须派生可编辑 Todo 变更 diff。用户确认能力绑定当前 diff、版本、来源快照和日期；任一事实变化都会使旧能力失效。
- 每日复盘文本与 Todo diff 分开确认，不能借复盘确认夹带排期、延续或分类写入。
- 当前产品不提供无人确认的 Todo 状态、排期、内容、历史或批量分类写入，也不提供固定模板 fallback 或另一套旧建议执行路径；新任务自动归类只使用受限持久工作与分类 Module authority。
- 所有成功、失败、恢复、授权和应用结果必须进入当前会话的事件历史或应用回执。

## 核心能力

### 每日复盘助手

输入：

- 当日 Day Todo
- 当日复盘草稿
- 当日完成、未完成、已延续、已变更、已废弃统计
- 相关任务链历史

输出：

- 今日事实摘要
- 未完成原因假设
- 明日风险提示
- 可行动建议
- 可选复盘文本草稿

约束：

- 不能改写每日复盘统计事实。
- 不能替用户自动提交复盘文本。
- 输出要区分事实、推断和建议。

### 习惯画像

烛龙可以根据历史轨迹提出阶段性画像，但只能作为可修正假设。

候选画像包括：

- 好大喜功型：经常创建大任务，子任务拆解不足，延续次数高。
- 拖延型：任务多次延续，完成集中在压力边界附近。
- 估时偏差型：每日任务量持续超过历史完成能力。
- 完美主义卡住型：任务变更多、完成少，大任务长期不收敛。
- 被动响应型：当日新增和回池频繁，原计划被外部事务打断。
- 碎片化切换型：大量小任务开始，但完成轨迹分散。
- 稳定推进型：大任务能拆解成子任务，并在多日内持续收敛。

约束：

- 画像必须带证据和置信度。
- 画像不能永久写入用户身份，只能作为某个时间窗口的分析结果。
- 画像文本不能羞辱用户，不能给医疗或心理诊断结论。

### 大任务拆解

烛龙可以帮助用户把一个大任务拆成子任务。

输入：

- 任务标题、描述、已有子任务
- 用户目标日期或可投入时间
- 历史同类任务完成情况

输出：

- 建议子任务列表
- 推荐执行顺序
- 风险点
- 需要用户补充的问题

约束：

- 子任务建议只能进入当前 AI 规划草稿与 Todo 变更 diff。
- 用户确认当前 diff 后才能创建子任务。
- 已经产生日轨迹的任务仍不能覆盖式编辑标题和任务边界；需要改变任务边界时仍走子任务或变更方案。
- 任务描述和附言是补充信息：任务池以及当前日、未来日的待完成任务可逐条追加、编辑或删除附言；历史、已完成和未完成日轨迹只读。

### 自动排期

烛龙可以提出排期建议。

输出类型：

- 从任务池安排到某个 Day Todo
- 从未完成池延续到目标日期
- 把大任务拆成多天推进计划
- 提醒某天任务量超过历史完成能力

约束：

- 烛龙不能无确认创建日轨迹。
- 对历史未完成任务，烛龙只能建议延续复制或废弃，不能建议无痕改期。
- 对未来计划，烛龙可以建议未来日期之间的调整，但用户确认前不落库。

### 分组与标签整理

烛龙只使用当前分类模型：每条任务链最多一个主分类，以及零个或多个平级标签。授权范围必须分开传递主分类与标签，不得扁平化成一组无类型名称。

烛龙可以在同一份可编辑分类草稿中：

- 为任务选择或建议新的主分类；
- 选择、新建或移除多个标签；
- 批量预览每条任务的 before/after 分类差异；
- 把新建的主分类与标签一并纳入当次原子提交。

规则：

- 主分类和标签是组织与分析维度，不是任务状态。
- 当前分类修改不得改写已冻结的历史日轨迹分类快照。
- 批量分类草稿必须允许用户修改，并以一次绑定当前草稿、来源快照与当前日期的原子确认应用。

### 新任务自动归类

新任务捕获不进入烛龙会话，也不要求逐项确认。晷迹会在任务与本机持久工作已经原子保存后，向当前 Provider 发送最小范围的标题、描述与 active 分类目录；优先选择现有分组／标签，确无合适项时才建立新项。

规则：

- 成功结果必须提供一个分组与一至三个 AI 标签；用户在快速输入中明确写下的标签必须保留。
- 任务创建不能等待 Provider。未配置、离线、限流或解析失败时保留任务，显示可理解状态并允许重试。
- Provider 不可用期间积累的历史工作没有付费授权；配置可用后必须由用户明确选择开始、跳过或稍后处理。此后在 Provider 可用状态下创建的新任务才自动获得 dispatch authorization。
- 401／403 等确定性配置拒绝立即阻塞全局 circuit；429、5xx、超时和断网使用全局退避，冷却结束只允许一条 half-open probe。不得让每条积压任务分别消耗完整重试次数。
- Provider execution identity 使用不透明 revision；不得保存 API Key 或 API Key hash。相同 URL、模型和凭证的重复保存不作废在途工作；真实身份变化才撤销尚未 checkpoint 的旧 claim。
- Provider 调用期间用户手动分类、任务内容或目录基线发生变化时，旧结果不得应用。
- 自动路径不能扫描旧任务，不能改历史快照，也不能取得排期、完成、延续、废弃、标题、子任务或附言写权限。
- 请求与诊断不记录 API Key、原始正文或原始响应；队列不进入同步或数据导出。

### 理论参照分析

烛龙不绑定 GTD、四象限、番茄、PARA、Zettelkasten 或其他任何单一理论。

它可以回答：

- 按某个理论看，我现在的问题是什么？
- 这个理论适不适合我？
- 如果不用这个理论，仅从我的轨迹看，我应该怎么调整？

约束：

- 理论只能作为镜头，不是产品默认真理。
- 推荐必须回到用户自己的日轨迹、延续次数、完成率、子任务收敛情况和复盘文本。

## 可补充能力

- 延续风险预警：某任务达到第 N 次延续时提示用户重新拆解或废弃。
- 承诺预算：根据过去完成能力提示今天是否承诺过量。
- 任务边界审计：发现标题过大或含糊时建议拆子任务。
- 复盘追问：根据当日结果生成 1 到 3 个复盘问题。
- 周期性模式发现：识别某些主分类、标签、日期或时间段更容易延期。
- 任务命名助手：把含糊任务改写成可执行版本，但已有日轨迹任务仍必须走变更方案。
- 冲突检查：发现同一天多个大任务都需要高认知投入时提示冲突。
- 废弃建议：对长期不收敛且不再符合目标的任务链建议废弃。
- 导出 AI 分析报告：生成 Markdown 报告，但不替代真实复盘数据。

## UI 入口

建议第一版提供：

- 左侧导航中的“烛龙”入口。
- Day Todo 右侧复盘区中的“让烛龙分析今日”按钮。
- 任务详情中的“拆解子任务”和“排期建议”按钮。
- 未完成池中的“分析延续原因”按钮。
- 设置中的 provider 管理入口。

如果 provider 未配置：

- 烛龙页面显示配置引导和《苦昼短》意象。
- Day Todo、任务池、未来计划、未完成池、已完成池仍完全可用。

## 风险评估

- 隐私风险：用户任务和复盘文本可能包含敏感信息。必须最小化发送范围，并让用户显式确认。
- 错误建议风险：AI 可能误判任务意图或低估工作量。除新任务当前分组／标签外的写入动作必须预览和确认；自动分类必须可由用户立即修改，且之后不得被旧工作覆盖。
- 产品心智风险：AI 可能喧宾夺主，让晷迹变成聊天工具。入口应克制，核心清单仍是第一层体验。
- 分类污名风险：习惯画像可能让用户感到被系统定型。画像必须是时间窗口假设，并带证据和置信度。
- Provider 锁定风险：如果只支持一家模型，会违背用户自定义 provider 的要求。provider 层必须抽象。

## 回滚方案

- 使用 feature flag 关闭烛龙 入口。
- 保留 provider 配置但停止发起请求。
- 已经由用户确认创建的任务、主分类、标签和复盘文本是普通领域数据，不随 AI 入口关闭而删除。
- 未应用的会话草稿可以随会话整体删除；已经形成的 Todo 历史和应用回执不能因此被改写。

## 验证门槛

1. Provider 配置、Keychain、健康检查与失败路径通过真实 App 验证。
2. 会话授权、加密 sidecar、事件历史与中断恢复通过真实持久化验证。
3. 任务成形覆盖规划简报、一次性规划委托、结构化输出、Todo diff 预览和原子应用回执。
4. 每日收尾覆盖事实快照、原因假设、独立复盘确认和 Todo 处置，不允许交叉授权。
5. 所有普通烛龙写入入口都必须证明未确认时零 Todo 变化，确认后只调用当前普通领域接口；新任务自动归类另须证明任务不依赖网络、用户覆盖优先与工作跨重启恢复。

## 监控指标

本地优先前提下，第一版优先记录本机诊断指标，不上传个人数据。

- provider 请求成功率、失败原因、延迟区间
- 会话、规划委托、Todo diff 和每日复盘草稿生成次数
- Todo diff 被确认、修改、失效或放弃的比例
- 应用后仍处于有限撤销窗口的批次撤销比例
- 用户关闭 AI 入口或清空 provider 的次数
- 隐私确认弹窗取消率
