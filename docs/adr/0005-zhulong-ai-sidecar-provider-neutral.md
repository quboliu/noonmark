# 烛龙 采用旁路 Agent 与 provider 中立架构

晷迹支持 **烛龙** 作为可选 Agent，但它不能成为普通清单功能的依赖。Day Todo、任务池、未来计划、未完成池、已完成池、每日复盘和数据包导入导出必须在没有 AI provider、没有网络或 provider 故障时完整可用。

**Consequences**

- 烛龙只能读取当前会话授权范围内的任务轨迹，并生成规划产物或 Todo diff。权限上限为允许时，用户主动提交新会话同时授权入口固定且已披露的初始范围；权限上限为询问时必须提供继续或暂不使用两个选择。扩大范围或改变实际数据接收方仍须重新显式确认；授权不按时间过期，模型和显示配置变化不重复询问。任何 Todo 变化都必须再次由用户确认。
- 烛龙遵循“本地广算、远程少发”：本机可以在授权下使用广泛历史生成证据，Provider 默认只接收当前意图所需数据和聚合结果。
- 烛龙不直接写入历史事实；创建任务、拆子任务、排期、延续、废弃、label 修改和复盘文本保存都必须经用户确认后走普通领域接口。
- provider 层保持中立，第一版必须支持自定义 provider，未来可以增加原生云 AI provider，但不能移除自定义 provider。
- Provider 故障时不静默切换数据接收方；第一阶段由用户明确重试或选择其他 Provider，切换前重新披露身份、权限和发送范围。
- API Key 进入 Keychain 或等价安全存储，不进入普通配置文件、日志、数据包或崩溃报告。
- 烛龙记忆、会话、规划草稿、事件历史、校准数据和 Provider 发送记录属于独立高敏感 sidecar 数据，默认不进入普通 Todo 数据包或同步；未来导出和跨设备同步必须单独授权并加密。
- 烛龙的习惯画像只作为时间窗口内的证据化假设，不作为永久用户身份。
- 《苦昼短》和衔烛龙意象属于烛龙的品牌与设计素材，不改变任务状态机和日轨迹规则。
