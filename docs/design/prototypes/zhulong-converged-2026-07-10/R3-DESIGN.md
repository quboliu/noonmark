# 烛龙任务成形 R3 收敛原型

> THROWAWAY PROTOTYPE — 用来验证选定交互模型能否承载完整任务成形闭环。它只使用内存状态，不连接 Provider、SQLite、Keychain 或真实 Todo 写入；验证结论应进入正式规格，原型代码不得直接进入生产。

## 一句话设计

一份持续成形的活简报承载委托边界，关键缺口以内联单轮 grill 解决；简报确认后，烛龙在可见运行线上自主工作，只在必须由用户决定的决策门停下，最后形成结构化计划并单独派生 Todo 变更 diff。

## 要验证的问题

1. 用户能否始终知道烛龙当前理解的目标、仍缺什么，以及自己的回答刚改变了什么；
2. grill 是否只出现在真正阻塞委托的字段，而不是形成固定问卷；
3. 规划委托后，用户能否看见烛龙做过的步骤、使用的依据、下一步和停机条件；
4. 结构化计划是否先于 Todo diff，并避免无证据日期、点数和兑现概率；
5. 规划委托、决策门确认和 Todo 原子应用是否保持三个独立授权动作。

## 共同视觉基线

- 继续使用真实 Noonmark Mac 宿主：`240px Sidebar`、页面自己的 `PageHeader`、贯穿窗口的 `300px Detail Rail`、系统字体与当前 App 的冷灰主题。
- 设计尺寸 `1320 × 820`；最小尺寸 `1180 × 760`。主内容 padding `20px 24px 40px`，一级区块间距 `12–16px`。
- 控件使用 `7–9px` 圆角、`1px #E6E6E9` 边线、`#2961C7` accent 与 `#EDF4FF` soft fill；不使用大型实心按钮、聊天气泡、Web Dashboard 或遮罩 sheet。
- `#7C5CFF` 只保留给烛龙导航图标及淡 active tint。
- PageHeader 下只显示真实状态带：共同定义、简报待审、规划运行、决策门、修订待确认、重委托完成、草稿待审、写入确认或完成；不显示固定题数或假进度。
- Detail Rail 始终检视当前字段、当前运行步骤或当前写入批次，不重复整页；事件历史在同一 rail 原位切换。

## R3 状态与传播

### 1. `focus` — 活简报与内联 grill

- 主区是一份纵向活简报，字段为：目标、用户取舍、完成标准、硬约束、可自主事项、烛龙假设、未决问题和数据范围。
- 已确认字段显示来源；当前缺口使用 accent-soft label rail，并在 field body 内展开一轮 grill。
- 第一缺口是“第一条可用路径”。用户可选每日收尾、任务成形或先比较；选择“先比较”只能生成依赖比较，不能静默确认字段。
- 空回答不能推进；`不知道`保留缺口并给出取得结论所需信息。
- 确认第一条可用路径后，字段生成新简报版本，并明确显示刚改变的字段和来源；旧版本继续可审计，下一步进入 `criteria`。
- Detail Rail 展示当前字段的用户原话、本地事实、烛龙假设、主要备选、回答影响与所需授权。

### 2. `criteria` — 完成标准与最后一个阻塞缺口

- 沿用同一份活简报，不打开新的问卷或会话页面；第一条可用路径已经显示为用户决定。
- 当前字段切换为“最低可接受完成标准”，用户可选端到端可用、全面可追溯、二者同时满足，或用自然语言改写。
- 空回答不能推进；确认后简报升级为 v0.6，阻塞缺口清零，才出现完整简报审查入口。
- Detail Rail 只检视完成标准的来源、建议依据、备选表达及其对验证策略的影响。

### 3. `brief` — 完整规划简报与单次委托

- 主区展示完整简报 v0.6，不再展开问答；每个字段区分用户决定、本地事实、烛龙假设和已授权自主事项。
- 顶部显示与上一版的字段级变化；允许返回继续修改或追加会话更正。
- 底部明确说明本次规划委托允许拆解、排序、风险检查，以及形成依赖顺序和滚动触发条件；不允许改变目标、扩大数据范围、浏览外部资料或写入 Todo。
- 用户点击“确认简报并委托规划”后才进入 `run`。简报实质变化必须重新委托。
- Detail Rail 展示本次委托的版本、数据范围、Provider 配置身份、自主边界和停机条件。

### 4. `run` — 可见的有界委托运行

- 主区顶部是紧凑运行契约，下面是纵向运行线：理解目标、核对本地事实、建立依赖地图、可行性审查、形成阶段地图、派生近期草稿。
- 每行只显示状态、实际产物和阻塞原因；完成步骤折叠，当前步骤展开，未开始步骤弱化。
- 初始运行不会瞬间完成。用户选择“运行到下一决策门”后，界面只推进已披露的步骤。
- 本轮决策门是：真实工程工作量尚未测量，是否允许先形成调查任务并暂不排具体日期。烛龙必须披露“证据不足”，不能伪造日期、点数或概率。
- 到达决策门后进入 `gate`，不会复用规划委托替用户作出取舍；修订与重新委托完成后，`run-resumed` 才产生“规划草稿 v1 已生成”回执，再由用户打开 `draft`。
- Detail Rail 展示当前步骤实际输入、证据、可验证世界约束、显式假设、备选动作、为何选择、下一步与停机条件。

### 5. `gate` — 证据不足的决策门

- 运行在可行性审查时停下，明确披露真实工程工作量尚未测量、缺少可比实现历史，因此不能承诺具体日期、点数或正式兑现概率。
- 用户可以授权先形成调查任务和滚动触发条件、要求只给宽范围并保留不确定性，或暂时不解决；没有选择不能继续。
- 决策门确认只授权这一项取舍，不复用规划委托，也不包含 Todo 写入。

### 6. `amendment` — 简报修订与旧委托失效

- 决策门结果写入新的简报 v0.7，并以字段级 diff 说明改变了哪些假设、约束或自主边界。
- 因简报发生实质变化，旧的一次性规划委托自动失效；系统必须显式告知用户，不能静默沿用。
- 用户审查并确认修订后，才可以重新委托剩余规划工作。

### 7. `run-resumed` — 重新委托后的可见完成

- 运行线保留决策门前后的完整记录，显示修订版本、重新授权事件和每一步实际产物。
- 只继续剩余的可自主步骤；完成后产生“规划草稿 v1 已生成”回执，但不自动打开草稿或写入 Todo。
- 用户明确选择审查规划草稿后才进入 `draft`。

### 8. `draft` — 结构化计划先于 Todo diff

- 先展示完整阶段地图、阶段依赖、滚动触发条件、近期细化范围和远期保留范围。
- 可行性审查明确显示“证据不足”：缺少真实工程工作量测量和可比实现历史，因此不产生具体日期、点数或正式兑现概率。
- 下方单独展示从成熟近期 slice 派生的 Todo 变更 diff；每项必须能回到计划节点和决策说明。
- 用户可以返回简报、查看 AI 决策说明、要求重跑某部分或进入 `apply` 审查；不得从计划正文直接写入 Todo。
- Detail Rail 展示证据、约束、主要备选、取舍、不确定性、反例、预期影响和所需授权。

### 9. `apply` — 当前具体批次授权

- 重复显示草稿版本、操作总数、目标范围、没有具体日期的原因和原子语义。
- Todo diff 是唯一执行依据；部分采用必须先拆分批次并形成用户修订版本。
- “原子应用 3 项变更”只授权当前批次，不等于规划委托、YOLO 权限或未来托管。
- 预检失败则整个批次回滚并进入事件历史。

### 10. `receipt` — 可追溯结果

- 列出三个普通 Todo 结果实体、来源计划节点、AI 应用批次和事件入口。
- 明确没有形成新的承诺、没有自动确认日期、没有产生长期记忆。
- 有限撤销资格单独显示；原应用事件不可改写。

## 原型内存状态

- `pathChoice`／`pathText` 与 `criteriaChoice`／`criteriaText` 分别保存两个阻塞字段的建议选择、自然语言改写和来源。
- `comparisonReady` 表示烛龙已补齐两条路径比较，但用户取舍仍未确认。
- `gateChoice`／`gateText` 单独保存决策门选择；简报修订确认和重新委托由独立业务阶段表达，不复用原规划委托。
- `lastCorrection` 保存 append-only 更正事件；更正发生在委托后时，`planInvalidated` 立即停用旧运行、草稿、diff、apply 与 receipt。
- `replacementRunAuthorized` 只在用户重新确认活简报并建立新委托后开启；新运行生成并审查新草稿前，浏览器 `popstate` 或直接旧 route 都不能恢复写入能力。
- 更正修订使用单调的新版本谱系；旧简报与旧草稿继续可审计，不回退覆盖。
- 所有输入在重新渲染后仍可见；页面 reload 可以清空，符合 throwaway prototype 无持久化原则。
- URL 只保存业务阶段：`step=focus|criteria|brief|run|gate|amendment|run-resumed|draft|apply|receipt`。不再使用 `variant`、prototype controls 或候选方案 switcher。

## 验证矩阵

- `focus` 空回答 fail-closed；“先比较”生成比较但不关闭缺口；`criteria` 确认完成标准后才出现简报审查入口。
- `brief` 确认前不能进入 `run`；`gate` 没有用户选择不能继续；形成 `amendment` 后旧委托失效，重新确认才进入 `run-resumed`。
- 委托后的追加更正必须使旧 run／draft／apply／receipt fail-closed；通过浏览器历史重开旧 draft 时，应用动作仍须不可用。
- 运行只推进可见步骤；`run-resumed` 完成后才出现规划草稿审查入口。
- 规划草稿包含完整计划、证据不足和独立 Todo diff；无伪精确日期、点数或概率。
- Todo 批次原子应用后列出结果、来源和没有形成承诺的说明。
- Provider 失败、本地模式、事件历史、1180×760 与长内容底部继续可达。

## 结论占位

待用户实际走通 R3 后记录：活简报字段是否足够、决策门是否过多或过少、运行可见性是否可信，以及能否进入正式 Mac UI 规格。
