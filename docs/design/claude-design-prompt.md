# 发给 Claude Design 的页面设计 Prompt

你是 Claude Design，请为一个 Mac 首发的 SwiftUI Todo 产品设计第一期界面。产品中文名是“晷迹”，英文名是 “suntrace”。请只负责产品界面、信息架构、交互和视觉方案，不要设计数据表、同步协议、后端或具体代码实现。

## 产品一句话

晷迹不是普通待办清单，而是一个围绕“每日任务轨迹”和“每日复盘”的 Mac Todo 产品。每一天写下的任务都必须留下不可删除的轨迹；跨日未完成的任务不能无痕移动，只能延续复制，并显示它持续了几天。

## 第一目标用户

需要每天计划、执行和复盘的人。他们不只是想记录任务，更想回看每一天承诺了什么、完成了什么、哪些任务拖延了、哪些任务被变更了、哪些任务被放弃了。

## 核心设计理念

- 每一天都是一个可回看的工作台。
- 今日任务是当天承诺，不是可随手抹掉的临时文字。
- 任务没做完不是消失，而是留下轨迹，再决定延续或废弃。
- 历史不是惩罚用户，而是帮助用户复盘真实行为。
- UI 要让用户很容易切换日期、回看历史、处理未完成。

## 技术和平台约束

- 第一版是 Mac 端产品。
- 使用 SwiftUI 作为实现前提。
- 只设计单主窗口。
- 视觉基调必须是亮色、清晰、克制、效率工具气质。
- 不要暗色首页，不要大面积黑色，不要营销落地页。
- 不要设计多窗口、菜单栏快速添加、Watch、小组件、账号登录或自动云同步。
- `Cmd+Z` 只作为有限撤销：可撤销当前日或未来计划里的误操作，但不能撤销历史事实。
- 烛龙是可选 sidecar；没有配置 AI provider 时，普通清单功能必须完整可用。

## 必须设计的一级入口

请设计一个 Mac 单主窗口，建议包含左侧导航、中央主工作区和右侧详情 / 复盘区。一级入口必须包括：

- Day Todo
- 任务池
- 未来计划
- 未完成池
- 已完成池
- 烛龙
- 设置

你可以调整布局，但这些入口必须清楚、可快速切换。

## 核心概念

### Day Todo

某一个自然日的任务工作台。用户可以快速切换日期，查看当天写了哪些任务、完成了哪些、未完成哪些、延续了哪些、变更了哪些。

Day Todo 有三种日期状态：

- 历史日：已锁定，只能回看和补写复盘，不能改写任务事实。
- 当前日：可以完成、撤销完成、变更、回池、废弃或延续任务。
- 未来日：可以提前排期和调整顺序，但不能提前完成或生成复盘。

### 任务池

尚未安排到任何具体日期的任务集合。类似待排期区域。

### 未来计划

已经安排到未来日期、但日期还没到的计划草稿。未来计划可以改到另一个未来日期，也可以回到任务池。

### 未完成池

按任务链去重展示所有存在未完成历史的任务。一个任务如果 Day 1 未完成、Day 2 延续后仍未完成，未完成池只显示一条任务；点开明细能看到 Day 1、Day 2 的未完成记录。

如果这个任务已经延续到 Day 3 且 Day 3 还待完成，未完成池仍显示它，但标注“已延续到 Day 3，当前待完成”，并提供跳转到 Day 3 的入口。

### 已完成池

按完成记录逐条展示，不按任务链去重。用于回看完成事实。每条完成记录必须展示这条任务的完成轨迹：从哪一天开始、延续到了哪几天、在哪一天完成。

### 烛龙

可选 AI Agent，用于复盘、习惯分析、任务拆解、排期建议和 label 分类。它不能替用户自动改任务，所有 AI 输出都应先是建议草稿，用户确认后才落入普通清单。

烛龙必须支持自定义 provider。未配置 provider 时，页面应显示配置入口、隐私说明和产品意象，而不是报错或挡住普通清单。

烛龙 可以使用李贺《苦昼短》作为完整 slogan 元素。请把它做成克制、可展开、可滚动或带仪式感的页面元素，不要在主工作区大段压迫用户。可用文本如下：

> 飞光，飞光，劝尔一杯酒。
> 吾不识青天高、黄地厚，
> 唯见月寒日暖，来煎人寿。
> 食熊则肥，食蛙则瘦。
> 神君何在？太一安有？
> 天东有若木，下置衔烛龙。
> 吾将斩龙足、嚼龙肉，
> 使之朝不得回、夜不得伏。
> 自然老者不死、少者不哭。
> 何为服黄金、吞白玉？
> 谁似任公子，云中骑碧驴？
> 刘彻茂陵多滞骨，嬴政梓棺费鲍鱼。

### 每日复盘

每个 Day Todo 都有复盘区。复盘区包含自动统计和用户手写内容。

自动统计包括：

- 当日总任务数
- 已完成数
- 未完成数
- 已延续数
- 已变更数
- 已回池数
- 已废弃数

手写内容包括：

- 今日总结
- 未完成原因
- 明日注意事项

## 任务状态

第一期只有这些状态：

- 待完成
- 已完成
- 未完成
- 已延续
- 已变更
- 已回池
- 已废弃

请为这些状态设计清楚但不过度花哨的视觉表达。状态要利于扫描，不要只靠颜色区分。

如果一个大任务有多个子任务，且只完成了其中一部分，父任务不要显示为新的正式状态；请把“部分完成 1/2”这类信息设计成进度标签或子任务进度展示。父任务仍按待完成、未完成、已延续或已完成等正式状态表达。

## 关键交互规则

### 当前日任务

当前日任务可以：

- 标记完成
- 当天撤销完成
- 添加子任务
- 延续复制到其他日期
- 变更为新任务
- 回到任务池，但必须在当天留下“已回池”轨迹
- 废弃任务链
- 调整当日优先级

当前日任务如果存在未完成子任务，不能标记为已完成。用户可以继续完成子任务，或把不再需要的子任务标记为已废弃；这些动作都需要在界面上留下清楚但克制的记录。

当父任务延续复制时，只复制未完成子任务。已完成子任务留在原日期；被延续的子任务需要在原日期显示“已延续到某日”，并在目标日期继续出现。

### 历史日任务

历史日任务不能：

- 删除
- 覆盖编辑
- 无痕改期
- 撤销已完成
- 修改当日优先级
- 通过撤销抹掉历史事实

历史未完成任务可以：

- 延续复制到某个日期
- 废弃任务链
- 查看明细

### 未来计划

未来计划可以：

- 改到另一个未来日期
- 回到任务池
- 调整未来日内优先级

未来计划不能：

- 标记完成
- 延续复制
- 生成复盘

### 任务变更

如果用户要改变任务定义，不是直接改标题覆盖旧任务，而是走“变更”。

界面要表达：

- 旧任务仍在当天列表里。
- 旧任务状态为已变更。
- 旧任务标注“被变更为：新任务标题”。
- 新任务自动出现在同一天，状态为待完成。

### 延续复制

跨日期继续推进任务时，必须用延续复制。

界面要表达：

- 原日期任务保留。
- 原任务状态变成已延续。
- 目标日期生成新的待完成任务。
- 显示延续次数，例如“第 2 次延续”或“持续 3 天”。

## 需要设计的核心页面

### 1. Day Todo 主页面

必须包含：

- 日期切换器：能快速切换前一天、后一天、今天、选日期。
- 日期状态提示：历史日、今天、未来日。
- 当日任务列表。
- 任务状态标识。
- 当日优先级表达。
- 快速添加任务。
- 从任务池排期入口。
- 每日复盘区。
- 任务详情区。

请重点优化“每天切换和回看”的体验。

### 2. 任务池页面

必须包含：

- 未排期任务列表。
- 新建任务。
- 排期到今天 / 明天 / 指定日期。
- 任务详情。

### 3. 未来计划页面

必须包含：

- 按日期分组的未来任务。
- 快速跳转到某个未来日期。
- 调整日期。
- 回到任务池。

### 4. 未完成池页面

必须包含：

- 按任务链去重的未完成任务列表。
- 每条显示未完成次数、延续次数、最近未完成日期。
- 已延续待完成状态。
- 延续到某日。
- 跳转到活跃日轨迹。
- 废弃。
- 明细展开：展示每个未完成日期。

### 5. 已完成池页面

必须包含：

- 按日期或完成时间查看完成记录。
- 每条完成记录显示任务链开始日期、延续日期列表、完成日期。
- 每条完成记录可展开查看子任务轨迹：每个子任务从哪天开始、延续到哪些天、在哪天完成或废弃。
- 跳转到对应 Day Todo。
- 复制为新任务。

### 6. 烛龙页面

必须包含：

- Provider 未配置状态：配置入口、隐私说明、《苦昼短》/ 衔烛龙意象。
- Provider 已配置状态：复盘分析、大任务拆解、排期建议、label 分类建议入口。
- AI 建议草稿列表：展示建议来源、证据、置信度、可采纳项和可拒绝项。
- 习惯画像区域：只作为时间窗口内的假设，必须展示证据，不要做永久人格标签。
- 所有写入型建议都必须有确认按钮，不能设计成自动执行。

### 7. 设置页面

必须包含：

- 数据导出。
- 数据导入。
- 同步端点入口占位。
- 原生云同步占位，标明未来支持。
- AI provider 配置入口：自定义 endpoint、model、凭证状态和测试连接。

不要设计登录注册。

## 视觉方向

- 亮色基调。
- 像 Vercel / Stripe 亮模式那样克制、干净、精确。
- 更像生产力工具，不像营销网站。
- 信息密度适中，适合长期每日使用。
- 不要大面积渐变背景，不要暗黑赛博风，不要装饰性卡片堆叠。
- 任务列表要可扫描，状态和日期要清晰。
- 历史轨迹要有“不可改写”的感觉，但不要压迫用户。
- 每日复盘要温和、清楚、可长期填写。
