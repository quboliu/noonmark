## 用户症状与影响

用户从搜索、回看或分类集合进入临时分类，再清除条件时不能可靠回到进入前的集合。更明显的是从带过滤条件的飞光页面进入 Sticky Note，再双击「在飞光中打开」，实现会直接清空搜索、分类与回看模式，没有返回原浏览位置的操作。

## 时间线

- 初版分类过滤只存当前 selection，没有保存进入前的集合。
- Sticky Note 来源导航通过直接清空过滤并切到最近集合保证目标可见。
- 正式 Spec review 指出两条临时导航都破坏浏览连续性。
- 真实 App 从带搜索条件的集合打开 Sticky Note 来源，旧实现稳定丢失条件；根修后可定位来源并原值恢复搜索、模式、seed 与选中条目。

## 复现与证据

在 `e2e` profile 对一条 Sticky Note 来源飞光建立搜索条件，切到 Sticky Note 后物理双击来源。旧实现切回飞光时搜索为空且无返回路径。修复后先定位并选中源条目，集合上下文出现低噪音「返回之前的浏览」动作；物理点击后搜索框、过滤值、原选择与条目数恢复，证据截图为 `ideas-source-browse-restored.png`。

## 排除的假设

- 不是源条目副本问题：Sticky Note 始终引用同一个 `IdeaID`。
- 不是 ScrollView 定位失败：目标在清空条件后的最近集合中可见，丢失的是被覆盖的浏览状态。
- 不能保留不匹配过滤并强行滚动：这样目标仍不在当前投影中，选择与可见集合会分叉。

## 根因与破坏机制

浏览状态散落在搜索文字、分类、模式、回看 seed 与选中 ID 五个字段中，临时导航直接逐字段覆盖，没有把它们视为一个可恢复的位置。

## 根因修复

引入一等 `IdeaBrowseLocation`，把过滤文字、分类、集合模式、回看 seed 与选中条目作为原子快照。分类临时集合与 Sticky Note 来源揭示分别保存独立返回位置；恢复动作原子应用快照，离开来源揭示页时也自动恢复，避免把临时集合泄漏到下次进入。

## 教训与永久约束

来源揭示与分类筛选都是临时导航，不是破坏性重置。浏览位置必须作为整体建模，包含过滤、模式、随机 seed、选择与可见的返回 intent。
