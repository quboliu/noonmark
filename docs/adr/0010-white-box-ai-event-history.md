# 晷迹采用白盒披露与 append-only 烛龙事件历史

晷迹把白盒作为全局产品原则：影响用户决定的数据使用、推断、假设、不确定性、自动化、状态变更和失败，先以轻量情境提示呈现，再进入主界面可回看的 **烛龙事件历史**。这在界面克制与全面知情之间取舍，避免把说明常驻铺满工作区，也避免纯 Toast 消失后无从追溯。

**Consequences**

- App 和烛龙只能追加事件，不能修改、重排或逐条删除。
- 用户只能按最近一段连续时间范围执行事件清理；清理后追加不含原文的范围、数量和时间标记。
- 事件只保存用户可读摘要和关联入口，不复制敏感任务或记忆正文。
- Provider 的实际请求与响应以凭证脱敏的 **Provider 发送记录** 保存在对应会话中；删除会话时删除正文，事件历史只保留无正文摘要。
- 设置页管理记忆、授权、Provider 和披露策略；主界面事件面板回答“刚才发生了什么”。
- 该决定提供领域层 append-only 语义，不承诺密码学防篡改；若未来需要对抗设备所有者改库，必须另建威胁模型和 ADR。
