# Web 一年交互演示基线

- Task-ID：`noonmark-web-self-hosted`
- 范围：当前已实现的个人自部署 Web 能力；不替代原生 `NoonmarkDemoSupport`，不宣称 Swift 跨引擎对账或 Mac format 7 兼容。
- 源码：`services/noonmark/internal/store/demo.go`；运行数据、数据库与报告全部位于外置 demo run。

## 运行与隔离

交互入口为 `scripts/web/run-demo`：每轮建立新的 demo run，构建后从终端读取本轮密码，完成重放与回读才在本机 loopback 启动服务。命令保持前台，按 Ctrl-C 会停止本轮进程；非终端输入须显式使用 `--password-stdin`，不接受 argv 密码或默认密码。

`scripts/web/test-demo` 使用同一生成流程，再运行真实浏览器的桌面／移动长滚动页面、底部速记、精选飞光与提交回读。UI 还原覆盖固定为 `1200×768` 的 220px 导航、280px 详情／复盘、14 天日期条、860×660 设置工作面及主题切换、飞光原位编辑、Sticky Note 墙视图／来源聚焦和真实月份日历；同时保留 `1440×1000` 与 `390×844` 两个长滚动尺寸。这里复用一年事实，未另建 UI 假数据。合成凭证只存于测试进程内存。报告位于当前 run 的 `reports/demo.json`、`reports/demo-browser.json`、`reports/demo-browser-evidence.json` 和 `reports/playwright-demo.json`，截图在 `reports/screenshots/`。

需要复用构建时显式传 `NOONMARK_DEMO_BUILD_ROOT`；入口先验证当前完整 source hash 和 manifest 中各产物 SHA-256，失配则拒绝启动，不使用旧分支或旧源码的产物。

`CreateDemo` 只接受 `NOONMARK_PROFILE=demo`，并检查外置根、随机 run UUID、`ownership.json`、UID、source hash 和实际目录一致。目标固定为该 run 的 `databases/instance`，不允许指定其他实例。既有任务、飞光、Day 或非零 sequence 一律拒绝重放。

函数自行初始化、认证配置、生成实例密钥、重放与关闭数据库；历史时钟注入期间不向调用者暴露 Store，不启动 HTTP 服务。重放结束后恢复真实时钟，再重新打开 SQLite、执行完整性与领域校验、核对提交 receipt 和 change batch 数量。只有全部通过，报告才标记 `ready`，启动脚本才可以开放交互。

重放失败会保留该 run 的最小运行证据，不把部分 fixture 当成可体验状态；下一次使用全新的 run，不清理或复用其他 run。演示密码由调用者提供，报告不记录密码、token、正文或运行绝对路径。

## 连续一年用户故事

锚点为实例 owner 时区的当前自然日，向前覆盖 365 个连续自然日，使用日历加日跨越夏令时和闰年边界。每天都通过真实命令创建一项任务、编辑其标题与说明、完成任务并保存复盘；没有直接插入业务表或一次性替换 snapshot。

四个滚动季度分别覆盖第 1–92、93–184、185–276、277–365 天。每隔 30 天安排一场完整功能故事，每季度三场。以下每项普通命令在每季度至少执行三次：

| 能力 | 重放行为与保留证据 |
| --- | --- |
| 快速捕获与编辑 | 每日创建、修改标题及描述，随后形成完成轨迹 |
| 任务池与排期 | 池内创建、排到当天、回池、排到未来、未来改期、回池、再排到当天完成 |
| 有限完成撤销 | 当天完成、撤销完成、再次完成；历史完成仍保留 |
| 延期 | 当天手动进度到 40%，延期至次日，再于次日完成；不增加延续次数 |
| 延续 | 待完成任务跨午夜结算为未完成，次日通过 `ContinueTrace` 延续并完成 |
| 废弃与重新启用 | 废弃后重新启用并完成，同时保留另一条未重新启用的废弃轨迹 |
| 子任务 | 创建、修改标题及难度、完成、撤销完成、再次完成、废弃、取消草稿及父任务完成 |
| 飞光 | 创建、编辑多行正文、加入与移出 Sticky Note；最后季度保留三条精选 |
| 飞光墓碑 | 删除另一条临时记录，保留清空正文的墓碑，用户集合不显示墓碑 |
| 每日复盘 | 每日保存总结、未完成原因与下一日提示；共 365 篇 |

最后一天额外保留 60 条待完成任务，前四条各带两项未完成子任务，供长滚动、焦点、中文输入、任务动作与多设备刷新验收；另保留 8 条未来计划、12 条池内任务，以及昨日两条尚未延续的未完成任务。

## 机器报告与门禁

报告包含日期范围、365 天声明、每类命令总计、四季度命令计数、领域实体与投影计数、持久 sequence，以及数据库重新打开成功标识。命令计数必须与 SQLite 中真实 receipt 和 change batch 回读一致；不能只依据构造脚本中的计划次数生成报告。

必须同时满足：

- 365 篇每日复盘，前 364 天锁定；今天仍可操作。
- 当前日至少 60 条待完成、任务池至少 12 条、历史完成至少 365 条。
- 真实未完成、废弃、飞光墓碑各不少于 12 条，Sticky Note 至少 3 条。
- 上表对应的 24 种命令，每季度各不少于三次。
- 重新打开实例后，领域计数与 sequence 一致，SQLite／外键／领域校验全部通过。

`TestDemoOneYearCommandsAndReopen` 运行真实 365 天重放及重新打开检查；另外两项门禁验证显式 demo 身份、路径约束及拒绝向既有事实重放。测试运行时通过 `scripts/web/run audit` 使用独立外置测试根；测试构造的 demo manifest 只用于该隔离根，不能授权访问真实演示或正式实例。

尚未实现的重复计划、分类、任务附言、烛龙、原生数据包互通不进入此报告，也不被表述为已验收。后续新增普通用户能力时，须同步扩展真实命令故事、四季度计数及交互验收。
