# ADR 0034：以独立周期实例呈现完整周期轨迹

## 状态

已接受。

## 情境

晷迹现有任务链同一时间最多只能有一个活跃日轨迹；延期和延续都表达同一承诺沿时间继续推进。周期计划却会让同一规则在多个日期分别形成承诺：某一天未完成，不能阻止下一天的实例出现，也不能把两个日期的结果覆盖成一个累计状态。

用户要求未来计划、未完成池和已完成池使用同一套呈现逻辑，并如实展示整个周期的每一个自然日，形成任务打卡视图感。连续完成天数、连续未完成天数或完成率只能是派生摘要，不能代替逐日事实。

## 决策

1. 周期系列的每个计划日建立独立任务链、任务定义和日轨迹。周期实例可以独立完成、未完成、延期、回池、变更或废弃。
2. 第一版使用嵌入任务链的不可变 `TaskCycleMembership` 记录系列身份、计划日、有限起止日期和规则。相同系列的描述必须一致，`seriesID + occurrenceDate` 必须唯一。
3. 第一版只支持最多 366 个自然日的有限日期区间，以及每天、工作日两种规则；创建、恢复、导入与同步都先验证同一个范围上限，再一次性物化全部计划实例，不引入无限后台生成器。
4. 周期轨迹由 Core 从真实任务链和日轨迹派生，连续列出日期区间内每个自然日。非计划日、跳过、今日待完成、未来计划和各历史结果使用不同状态。
5. 未来计划、未完成池和已完成池复用同一周期轨迹。页面只按是否包含未来、未完成或完成事实决定入选，并改变轻量强调色与摘要；入选后不得过滤其他日期状态。
6. 周期实例在三类聚合页不再作为普通任务逐条重复展示；Day Todo 仍把当天实例作为普通可执行任务。
7. 周期成员随 task-chain 同步记录传输；同一任务链收到不同周期成员关系时按身份碰撞 fail-closed。全新周期系列的所有 task-chain 及其结构依赖必须按 `seriesID` 组成一个原子同步 component，不能逐实例提交后触发系列完整性误拒。SQLite 以受约束 JSON 列保存，数据包格式升级为 v5。
8. 周期成员的计划日是系列中的固定位置；实例延期或重新排期后，活跃日轨迹可以移动到另一日期。周期轨迹分别派生原计划日事实、当前未来目标、未完成结果和完成结果；各聚合页以自己的语义目标决定入选、强调和点击目的地，其他计划日仍可回看。
9. Snapshot 完整性必须证明有限日期区间内每一个被规则选中的计划日恰有一个周期成员；缺失计划日不得降级显示为非计划日。

## 影响

- 优点：每日事实与现有任务链约束保持一致；任意页面都能看见完整周期，而不是只看连续天数或异常计数。
- 优点：周期关系随任务链跨设备与导出包完整保存，不引入第二套任务状态机。
- 限制：第一版不能编辑周期规则，也不生成无限未来实例。改变规则应在后续设计中形成新规则版本或新系列，不能覆盖历史成员。
- 限制：周期系列描述嵌入每个实例，依赖 snapshot 完整性验证防止同系列分叉；若未来需要频繁编辑系列元数据，应提升为独立 aggregate。

## 风险与回滚

- 重复计划日或分叉规则会让投影失真；Core、SQLite 和同步边界均 fail-closed。
- 大日期范围会一次性产生大量任务；领域创建、snapshot 恢复、导入与同步边界已统一限制为最多 366 个自然日。正式创建 UI 仍须向用户说明实例数量并要求确认。
- 功能位于独立 feat 分支，未合并前可直接丢弃分支并执行开发数据 clean cut 回滚；普通任务没有周期成员时完全沿用旧投影。

## 验证

- `TaskCycleSeriesTests` 覆盖独立任务链、每天／工作日、全日期轨迹、三页语义入选和完整性拒绝。
- Storage 测试覆盖 SQLite 往返与 v5 数据包导出导入；Sync 测试覆盖 task-chain record 往返、全新系列原子合并、超长描述拒绝和分叉成员拒绝。
- `TaskCycleSeriesTests` 证明三页只改变入选语义、不裁剪完整轨迹，并覆盖计划日缺失、未来实例重新排期，以及延期目标待完成、完成与未完成后的投影。
- 交互演示 fixture 通过真实领域接口重放十三天周期系列，并把最后一个实例重新排期到区间外次日，再从 SQLite 回读；真实 `.app` 必须在三类聚合页发现唯一完整轨迹及全部日期标识，从 Future 的重新排期格和 Completed 的历史格进入各自对应 Day Todo。
