## 用户症状与影响

移动右栏打开后会话失效，登录页的 Shift+Tab 被已消失右栏的焦点循环吞掉；重新登录还可能留下不可交互的主区。从任务菜单打开详情后关闭，焦点尝试回到已隐藏的菜单项，未回到任务行。

## 时间线

原生 UI 结构门禁转绿后，代码复核提出焦点生命周期假设。主 agent 在两个全新隔离 audit 实例分别通过真实服务与浏览器复现；未使用用户正在体验的实例撤销会话或造资料。发现发生在公开演示替换前。

## 复现与证据

- audit `7854e2db-af5c-49a9-a20b-14eb4753a3f6`：390px 视口登录→展开右栏→通过真实 API 撤销本次会话→轮询收到 401 回登录→Shift+Tab；`auth-focus.json` 中 `trapped=true`。
- audit `7513b155-9dc3-4e6a-8e06-d30fef19477d`：行内新增→任务菜单→查看详情→关闭；`menu-focus.json` 中 `returned=false`。

## 排除的假设

输入法与异步草稿未参与以上两个复现。会话撤销成功并已经显示登录页，问题不是后端认证失效；菜单路径使用真实 DOM 点击，问题不是浏览器未产生点击事件。

## 根因与破坏机制

焦点逻辑只绑定栏位布尔状态，没有绑定工作面是否仍存在。认证结束没有结束右栏监听；菜单关闭后仍保留菜单项作为返回目标。这两个分支都把已经失效的 UI 引用当成有效焦点边界。

## 根因修复

结束会话统一关闭暂态工作面；移动焦点循环同时绑定有效认证状态，不随每次 busy/轮询重建。详情入口记录稳定任务行，关闭时在重新渲染后确认目标仍可见，必要时按任务身份重新找回当前行。

## 验证结果

旧构建两个原始症状已判红；修复后 5 项原生交互专项、一年演示门禁及完整 Linux `make check` 均通过。年度门禁从任务菜单进入详情，并实际撤销移动会话再重新登录，覆盖两个原始症状。证据见[UI 验证记录](../../tasks/noonmark-web-ui-parity/verification.md)；修复 SHA 已回填。
