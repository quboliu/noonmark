# 保持原生下拉菜单，不为面板样式走自绘弹层

**Status**: Accepted  
**Date**: 2026-07-29  
**Risk**: S 级——纯外观决策，不改代码、不改数据

## Context

右栏统一改造后复核全 app 下拉菜单（页面头部「视图」切换、任务行右键菜单、`…` 溢出菜单、设置 Picker），其弹出层全部是 SwiftUI 原生 `Menu` / `Picker` / `contextMenu`，由系统以 NSMenu 绘制。面板呈现为浅模式下的半透明青灰底与近黑文字，与右栏新的克制视觉语言存在观感落差，需要决策是否美化。

事实边界：NSMenu 的背景、文字颜色、行高与高亮样式由系统渲染，跟随系统外观与系统强调色，没有公开接口可以修改；私有接口硬改既不稳定也不可维护。

## Decision

- 动作类下拉（右键菜单、溢出菜单、页面头部切换、设置 Picker）保持原生 NSMenu，不追求面板底色、字体颜色的定制。
- 原生菜单内只做内容层优化：需要时用 SF Symbol 图标、分隔线、分组标题与勾选态提升精致度，面板样式本身不动。
- 自绘 popover 弹层只保留为一种例外手段：仅当某个下拉承载富内容（带说明的选择器、色板预览等）而非动作列表，且被明确点名验收时，才允许单点替换；替换时必须补齐键盘导航、Esc／点击外部关闭、屏幕边缘定位与 VoiceOver，不得全 app 推广。
- 本决策不改任何现有代码。

## Consequences

- 下拉菜单外观继续跟随系统，浅／深色模式与系统强调色变化时自动一致，不产生维护负担。
- 键盘上下导航、打字定位、悬停追踪、屏幕边缘翻转与 VoiceOver 等原生行为完整保留。
- 右栏与菜单之间的观感落差被接受为平台惯例成本；用户对本产品之外的 Mac 应用也有同一菜单长相，不构成产品级缺陷。

## Rejected alternatives

- 全 app 统一替换为自绘下拉：工程量大（数十处调用点）、右键菜单系统绑定深、收益仅为面板配色，且丧失原生交互行为，性价比不成立。
- 用私有接口修改 NSMenu 外观：无稳定性保障，随系统升级随时失效。
- 立即对「视图」切换器等个别下拉做自绘样板：当前无明确痛点，属于 speculative 工作；待真实不满意时再单点启动。

## Verification

本决策为保守现状型，无代码改动，无需新增验证。若未来触发单点自绘例外，验收必须覆盖：真实 App 内的键盘全流程操作、Esc 与点击外部关闭、VoiceOver 朗读，以及与原生菜单的逐项行为对齐清单。

## Rollback

无代码改动，无回滚面。未来若单点自绘弹层上线后不及预期，以该组件对应 commit 为边界 `git revert` 恢复原生 `Menu` 调用即可。
