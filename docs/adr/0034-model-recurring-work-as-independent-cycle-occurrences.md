# ADR 0034：以重复任务聚合独立实例与完整轨迹

## 状态

已被 ADR 0038 部分取代。独立父实体、日实例、完整轨迹、有限物化、规则修订、同步原子性和转换身份继续有效；四个状态页共享父计划投影及重复实例回池的决策不再有效。本文旧 full-state commit transport layout 已由 ADR-0046 取代。

## 情境

晷迹现有任务链同一时间最多只能有一个活跃日轨迹；延期和延续都表达同一承诺沿时间继续推进。周期计划却会让同一规则在多个日期分别形成承诺：某一天未完成，不能阻止下一天的实例出现，也不能把两个日期的结果覆盖成一个累计状态。

用户要求任务池、未来计划、未完成池和已完成池使用同一套呈现逻辑，并如实展示整个重复区间的每一个自然日，形成任务打卡视图感。连续完成天数、连续未完成天数或完成率只能是派生摘要，不能代替逐日事实。

## 决策

1. 重复任务的每个计划日建立独立任务链、任务定义和日轨迹。重复实例可以独立完成、未完成、延期、回池、变更或废弃。
2. 重复任务是独立 aggregate，拥有稳定身份、标题、描述、有限起止日期、规则、内容时钟和 append-only 取消事实。任务链上的 `TaskCycleMembership` 只记录父实体身份与原计划日，`seriesID + occurrenceDate` 必须唯一。
3. 第一版只支持最多 366 个自然日的有限日期区间，以及每天、工作日两种规则；创建、恢复、导入与同步都先验证同一个范围上限，再一次性物化全部计划实例，不引入无限后台生成器。
4. 重复轨迹由 Core 从真实任务链和日轨迹派生，连续列出日期区间内每个自然日。非计划日、跳过、回池、今日待完成、未来计划和各历史结果使用不同状态；`cancelledDraft` 只有同时存在父实体取消事实时才表示跳过，不能把普通回池误报为删除。
5. 独立的“重复计划”模块统一管理全部父实体，包括尚未开始、执行中、自然结束和提前停止的计划。任务池、未来计划、未完成池和已完成池复用同一重复轨迹作为状态投影：任务池只在至少一个实例真实回池时收纳父实体；仅有今天或未来执行义务、自然结束、停止后只余历史，或未来实例已全部跳过／取消且没有回池实例时不入选。未来计划、未完成池和已完成池分别按是否包含未来、未完成或完成事实决定入选，并改变轻量强调色与摘要；入选后不得过滤其他日期状态。
6. 重复实例在四个聚合页不再作为普通任务逐条重复展示；Day Todo 仍把当天实例作为普通可执行任务。
7. 重复任务拥有独立同步记录；同一任务链可以从普通任务单向获得重复成员身份，以支持既有任务转换，但已属于两个不同重复任务的身份碰撞仍按冲突 fail-closed。全新重复任务、所有 task-chain 及其结构依赖必须按 `seriesID` 组成一个原子同步 component，不能逐实例提交后触发系列完整性误拒。上传的 100 条限制是普通批次软上限，单个系列超过上限时必须整组提交。同步结果按用户任务聚合：一个重复任务只计一条，并分别补充新增／更新中的重复任务数量，不显示内部实例或 record 数。Local Folder／iCloud Drive transport 以包含完整当前状态的不可变 commit 文件原子发布，并记录父 head；并发设备形成多个 head，读取时合并 head，后续 commit 再收敛，不能让逐 record 文件成为发布事实源。SQLite 以独立表保存父实体，数据包必须完整保存父实体与成员关系。
8. 重复实例的计划日是重复任务中的固定位置；实例延期或重新排期后，活跃日轨迹可以移动到另一日期。重复轨迹分别派生原计划日事实、当前未来目标、未完成结果和完成结果；各聚合页以自己的语义目标决定入选、强调和点击目的地，其他计划日仍可回看。
9. Snapshot 完整性必须证明有限日期区间内每一个被规则选中的计划日恰有一个重复实例；缺失计划日不得降级显示为非计划日。
10. `跳过本次` 只取消一个原计划日仍在今天之后、且当前仍安排在今天之后待执行的实例；`停止重复` 只取消所有满足同一条件的实例。两者都保留父实体、实例身份、今天实例和历史结果；今天或历史实例后来延期到未来时仍属于积压任务，不得被停止操作吞掉。取消结果以 append-only 事实保存，防止旧同步记录复活。
11. “重复计划”作为计划侧栏中的一级模块，按父实体而非日实例计数，并始终提供完整详情和轨迹。任务池、未来计划、未完成池和已完成池在存在符合该页语义的重复任务时固定显示“重复任务”区，不受普通任务按分组／不分组设置影响。每个父实体只显示一行，完整轨迹默认收起；固定区不是主分类 section，所以父项始终在行内显示自己的当前主分类和标签。该管理行不增加任务池任务数量，内部 `cancelledDraft` 取消事实也不得投影成真实回池任务。Day Todo 仍显示当天可执行实例，并以轻量标识说明其重复规则。
12. 新建重复任务复用普通任务输入：仅当 draft 以 `/重复` 或 `/repeat` 开头时打开重复配置，并继续解析同一输入中的 `@分组` 与 `#标签`。页面标题区不提供独立“新建重复任务”按钮；全局快速记录使用同一语法。
13. 既有任务通过任务行右键菜单或详情 `…` 的“转为重复任务…”进入配置。任务池任务与今天／未来的待完成任务沿用原任务链、定义、规划子任务、分类、标签、附言和轨迹作为首个实例；锁定历史事实不改写，只复制可编辑内容与当前分类，从今天建立新的系列。无标题任务允许在配置中补充标题；既有分类通过继承来源与稳定 ID 复制，归档分类不按名称重建。标题补充、转换与所有新实例的分类提交在一个 SQLite transaction 中落盘。

## 影响

- 优点：父计划管理与实例执行清单职责分离；每日事实与现有任务链约束保持一致，状态页仍能看见完整重复区间，而不是只看连续天数或异常计数。
- 优点：重复关系随任务链跨设备与导出包完整保存，不引入第二套任务状态机。
- 限制：第一版不能编辑重复规则，也不生成无限未来实例。改变规则应在后续设计中形成新规则版本或新重复任务，不能覆盖历史成员。
- 优点：父实体成为标题、规则和生命周期的唯一权威，避免在几十个实例之间扇出修改并制造同步分叉。
- 限制：第一版仍不支持覆盖历史的规则编辑；改变规则应形成有明确生效日期的新规则版本或新重复任务。

## 风险与回滚

- 重复计划日或分叉规则会让投影失真；Core、SQLite 和同步边界均 fail-closed。
- 大日期范围会一次性产生大量任务；领域创建、snapshot 恢复、导入与同步边界已统一限制为最多 366 个自然日。正式创建 UI 会在提交前明确显示将产生的实例数量。
- 项目尚未发布且执行开发数据 clean cut，不提供旧 schema 迁移或双写灰度。发布前先在独立 feat 分支通过十天真实 App 演示，再合并；回滚只能回到前一提交并执行 `scripts/reset-dev-data`，不得尝试让旧二进制读取 v13 数据。
- 运行监控以同步 audit 中的 conflict／waiting 记录、commit head 数量、SQLite 完整性回读、数据包 canonical round-trip 和真实 App console failure 为准；任一结构组件不能闭合时整组拒绝，不部分落库。

## 验证

- 本节记录 ADR 0034 落地时的历史验证范围；四个状态页父计划投影、重复实例回池及其对应测试已由 ADR 0038 取代。
- `TaskCycleSeriesTests` 继续覆盖独立父实体与任务链、每天／工作日、全日期轨迹、独立重复计划集合、既有任务转换、跳过本次、停止重复和完整性拒绝；同步测试另外覆盖普通任务单向获得重复身份、分叉身份拒绝和父任务聚合计数。
- Storage 测试覆盖 SQLite 往返、当前数据包导出导入，以及超过 100 条时不拆分系列；Sync 测试覆盖父实体与 task-chain record 往返、取消事实合并、全新系列原子合并、commit 发布前／发布后故障注入和分叉成员拒绝。
- ADR 0038 的验证证明任务池、未完成和已完成零重复泄漏，未来计划只显示窗口内具体实例，Day Todo 仍按日期显示执行事实，重复计划保留完整轨迹。
- 交互演示 fixture 继续通过真实领域接口重放重复任务，并从 SQLite 回读；真实 `.app` 必须从一级“重复计划”模块发现全部父项，在 Future 看见窗口内具体实例，在 Day Todo 看见当天重复标识，且任务池、未完成和已完成不出现父项或实例。独立 mutation E2E 继续通过真实输入框的 slash command、任务行右键菜单和详情 `…` 分别创建／转换系列，覆盖空标题补名、归档分类继承与持久化失败完全回滚，再重启并以 SQLite 对账。
